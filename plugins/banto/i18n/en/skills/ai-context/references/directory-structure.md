# Directory structure (the AI's jurisdiction)

> This file doubles as a **read contract for external tools** (linked from the README). Bucket names,
> prefixes, and gitignore distinctions are treated as compatibility surfaces — when changing them, note it in the CHANGELOG.

## store layout (baseline)

Knowledge gathers in the central store, and repos hold only code (store-first).

```
<store_root>/                      # default ~/ai-context-store (override via AI_CONTEXT_STORE_ROOT)
├── .ai-context-store              # marker (prevents mistaking it for a code repo; store identifier)
├── .mapping.json                  # cwd → project resolution table (per-machine; never committed to the store)
├── _shared/                       # cross-project shared knowledge
└── <project>/                     # 1 project = 1 dir (scaffold registers / generates)
    └── … buckets below
```

```
<base>/                  # = <store_root>/<project>/ (SessionStart injects the absolute path)
├── decisions/           # design decision logs (flat; author attributed in the file name) ← store-shared
├── docs/                # reports / records (flat)                ← store-shared
│   └── research/        # research-agent output                   ← store-shared
├── learnings/           # lessons / learnings (personal state)    ← store-shared
│   └── <author>/        #   member namespace
├── workspaces/          # per-WS work state (new layout; personal state) ← store-shared
│   └── <author>/        #   member namespace
│       └── [scope] topic/
│           ├── workspace.md   # WS definition (branch / deps / related docs)
│           ├── tasks.md       # this WS's active tasks (equivalent to the old active.md)
│           └── tasks-old/     # Phase archive (equivalent to the old tasks/old)
├── tasks/               # legacy task management (unmigrated projects only) ← store-shared
│   ├── active.md
│   └── old/             # completed (YYYY-MM-DD_phase-name.md)
├── sessions/            # checkpoints (personal state)
│   ├── pending/<author>.md     # unconsumed checkpoints (relocated from the old checkpoints/pending.md) ← store .gitignore
│   └── consumed/<author>/      # consumed checkpoints (per-author)                  ← store .gitignore
├── WORKSPACE.md         # lightweight pointer (per-checkout)       ← store .gitignore
├── DASHBOARD.md         # hook-managed overview (per-checkout)     ← store .gitignore
└── *-combined.txt       # search text layer (auto-regenerated by a hook) ← store .gitignore
```

**Attribution principles**:
- **Shared knowledge (`decisions/` / `docs/`) = flat**. Who it belongs to is expressed by the author attribution in the file name (`..._{github-account}.md`).
- **Personal state (`tasks/` / `sessions/pending` / `sessions/consumed` / `learnings/` / `workspaces/`) = `<author>/` scope**, namespacing them so members don't collide.
- The old `checkpoints/` bucket is abolished. `checkpoints/pending.md` is relocated to `sessions/pending/<author>.md`.

- **grandfather (legacy)**: projects that have an existing in-repo `.ai-context/` keep using the same bucket
  structure on the in-repo base until migration (`/ai-context migrate`) (read/write as before).
  Nothing new is generated.
- The store's gitignore distinctions are managed centrally in `<store_root>/.gitignore` (no per-project .gitignore).

**Do not touch the project's main documents (`docs/requirements.md`, etc.).**

| Location | Purpose |
|------|------|
| `decisions/` | Design decision logs (shared, flat, file-name author attribution) |
| directly under `docs/` | Report / record artifacts (shared, prefix required) |
| `docs/research/` | research-agent investigation results (shared) |
| `learnings/<author>/` | Lessons / learnings (personal state) |
| `workspaces/<author>/<topic>/tasks.md` | Tasks in progress (new layout, bundled into a WS) |
| `workspaces/<author>/<topic>/tasks-old/` | Completed phases (new layout) |
| `tasks/active.md` / `tasks/old/` | legacy (read fallback for unmigrated projects) |
| `sessions/pending/<author>.md` | Unconsumed checkpoints (old `checkpoints/pending.md`) |
| `sessions/consumed/<author>/` | Consumed checkpoints |

## Fixed prefixes directly under docs/

Except for `docs/research/`, **always** use the following prefixes. Enforced by the hook.

```
[Status]      status / progress / situation reports
[Design]      design exploration, plan, proposal, discussion draft (pre-decision)
[Guide]       how-to, explainer, overview, architecture walkthrough, onboarding
[Audit]       audit / analysis / inventory (security/perf audit, comparison, inventory)
[Review]      code review results
[QA]          QA test reports, E2E results
[Memo]        short note, jot, record
[Index]       index of other documents (a true index)
```

Pick by intent: design / plan / proposal → `[Design]` / how-to / explainer → `[Guide]` / progress / situation → `[Status]` / audit / analysis → `[Audit]`.
Example: `[Design] payment-redesign-2026-06-23.md` / `[Guide] onboarding-2026-06-23.md`

**NEVER**: invent a new prefix on your own. Consult the user if needed.
