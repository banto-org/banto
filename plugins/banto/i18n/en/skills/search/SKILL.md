# Search — Internal Search (Claude-native)

> **Search base (store-first)**: in this skill, `{base}` refers to the ai-context base. Search under the absolute path that the SessionStart/PreCompact hook injects as "ai-context base: &lt;absolute path&gt;" (when unknown, resolve it with `sh "$CLAUDE_PLUGIN_ROOT/scripts/_ai-context-paths.sh" --resolve "$PWD"`).

When the user is conversing in Japanese, respond in Japanese (write the search report in Japanese too).

## search vs research

| | `/search` (this skill) | `/research` |
|---|---|---|
| Scope | **Internal**: `{base}/decisions/` `docs/` + conversation history + `extra_docs_dirs` | **External**: Web, GitHub, arxiv, X, official docs |
| Web access | **None** | Yes (WebSearch + research-agent) |
| Result | References / summaries of existing files | New files saved under `{base}/docs/research/` |
| Latency | fast: seconds / deep: minutes | minutes (parallel launch of research-agent) |

**Rule of thumb**: do you already have it or not. Have it → `search`; don't have it → `research`.

## Search targets and data layers

| Path | Contents | Freshness |
|---|---|---|
| `{base}/decisions/` `{base}/docs/` | Design decisions, reports, research | Search the raw files directly |
| `{base}/full-combined.txt` + `sessions-cache/` | The above + conversation history (including content lost to compact), concatenated into one text | SessionStart daily (throttled bg) + on-demand at the start of the deep path |
| `.store-index.db` at the store root | **Cross-store FTS5 section index** (every project's md, BM25-ranked with line ranges. `sessions/` (checkpoints) are excluded from the index — conversation history is covered by full-combined on the deep path) | Auto-regenerated by hooks at SessionStart / on store writes (scripts/store_index_gen.py; a derived artifact, never committed) |
| `{base}/search-lexicon.md` | **Search lexicon** (concept ↔ translations / synonyms / abbreviations) | Appended on a successful deep path (see below) |
| The project's `docs/` `specs/` etc. | Added via `extra_docs_dirs` in `{base}/config.json` | Included in full-combined generation |

## Search procedure

### Step 0: Read the lexicon

If `{base}/search-lexicon.md` exists, Read it and pull the terms from matching lines into your expansion (skip if absent).

### Step 1: Query expansion (3 tiers, weighted)

Expand the query into **weighted groups** by the following rules:

1. **Tier1 (×1.0) = synonyms**: put Japanese synonyms + **English translations** + katakana spelling variants + abbreviations in the same group (always assume the records may be in English; e.g. 「漂流」→ drift).
2. **Tier2 (×0.6) = near concepts**
3. **Tier3 (×0.3) = adjacent concepts**: put "similar but different in intent" terms here (monitoring → auditing). Pick them up, but don't let them dominate.
4. **Decompose question forms**: "why was X deprecated" → make `[X]` and `[廃止|supersede|撤廃]` into **separate Tier1 groups** (the multi-group-match bonus acts as a soft-AND).
5. **Split compound terms**: "ProjectX drift" → `[ProjectX]` + `[漂流|drift]`
6. Short ASCII tokens (PR/WS/KD) can be passed as-is (the script adds `\b` boundaries).

### Step 2: fast path (default, seconds)

Score with the ranking script:

```bash
python3 "$CLAUDE_PLUGIN_ROOT/scripts/ai_context_search_rank.py" \
  --base "{base}" --top 8 \
  --groups '[[1.0,["認証","auth","OAuth"]],[0.6,["認可"]],[0.3,["ログイン"]]]'
```

- Treat `confident: false` (top score < 1.0) in the output JSON as a **zero hit** → go to Step 4
- `confident: true` → go to Step 3

### Step 2.5: 3-layer retrieval (token-budget control; when there are too many hits / you want a full overview)

When there are many hits, or for requests like "give me an overview as a list" or "the history in chronological order", add `--layered` and retrieve progressively across the 3 layers **index → timeline → full** (the claude-mem 3-layer retrieval pattern: read from the cheap layer first and Read-open only the files you need, to save tokens):

```bash
python3 "$CLAUDE_PLUGIN_ROOT/scripts/ai_context_search_rank.py" \
  --base "{base}" --top 8 --layered --index-top 5 \
  --groups '[[1.0,["認証","auth","OAuth"]],[0.6,["認可"]]]'
```

The output is `{confident, layers:{index, timeline, full}}` (without `--layered`, `{confident, results}` as before / compatible). How to read each layer and the display order:

1. **index (cheapest; read first)**: an index compressing the top `--index-top` entries into a single line of `path / score / terms (matched terms)`. Present only this first and narrow down the candidates to open.
2. **timeline (chronological context)**: a column of all hits ordered **newest first** by the date at the start of the filename (`YYYY-MM-DD`). Use it to survey history and supersede relations (entries without a date go last).
3. **full (last; right before Read)**: the conventional detailed `score / path / hits` lines. Read only the files you decided to open from index and timeline.

If index alone suffices, don't open full. For history questions, present timeline as the main view. If there's a confident hit, go to Step 3 (verify only the files you decided to open).

### Step 2.7: Cross-store quick path (when cross-project intent is detected)

When the query signals **outside the current project** ("in another project", "somewhere before"), query the FTS5 section index directly before going deep (1ms, top 8 by BM25 with line ranges):

```bash
sh "$CLAUDE_PLUGIN_ROOT/scripts/store-query.sh" --all auth OAuth
```

- Read **only the hit line ranges** (offset/limit) and go to Step 3 verification (no whole-file reads)
- exit 1 (no sqlite3 / no index) → continue to the Step 5 deep cross-store route as before (fail-open)
- Also usable for narrowing within the current project (without `--all` it defaults to the current project). Terms shorter than 3 characters automatically fall back to a LIKE scan

### Step 2.8: From derived records to the primary document (`--related` traversal)

When a hit is a derived record (a workspace ledger, tasks, `[Index]`, `[Status]`, etc.), trace back to the primary document (a decision) before answering:

```bash
sh "$CLAUDE_PLUGIN_ROOT/scripts/store-query.sh" --related <unique fragment of the relpath>
```

- The output is a bidirectional edge list: `→ references (related:)` and `← referenced by`.
- Read-verify the decision you traced to before moving to Step 3 (don't answer from the derived record's content alone).
- Lesson from the R8 benchmark: landing on a checkpoint / ledger without tracing back to the primary document produced wrong answers. Don't stop at the derived record.

### Step 3: Verify (Read and judge)

Read the top 3–5 files and **judge relevance yourself**:

- Exclude polysemy mismatches (e.g. a document where "harness" means wiring).
- Exclude self-references (the very document you're writing now, or an evaluation table that merely quotes the query).
- Check supersede relations (has an old decision been overridden by a newer one?).
- Check whether you landed on a derived record — if so, trace back to the primary document via Step 2.8's `--related`.
- If the hit is a `[Ref]` card (doc_type=ref), the real content lives remotely — when you need the content itself, use `research` to pull the text in.

### Step 4: Second pass on zero hits (once only)

Redo Steps 1–2 with a different synonym set (flip the translation direction, expand abbreviations to full names, change the split granularity). And if `confident: false` → escalate to the deep path in Step 5.

### Step 5: deep path (parallel haiku, minutes)

**Triggers**: still zero hits after the second pass / "thoroughly", "everything" / "in other projects" (cross-store) / "we talked about this before" (conversation history). History and cross-store queries **may start here**, skipping fast.

0. Record the start time (report the wall-clock time). For history search, first update full-combined:
   ```bash
   python3 "$CLAUDE_PLUGIN_ROOT/scripts/ai_context_combined.py" --project-root "$PWD" --scope full
   ```
1. **Launch 3–5 `search-agent`s (model=haiku) in parallel within one message**. The standard division of roles:
   - (a) Japanese spelling-variant agent: `{base}/decisions/` `{base}/docs/`
   - (b) English / code-term agent: the same paths
   - (c) cross-store: run `store-query.sh --all` directly first (no agent needed, 1ms). Only in environments without the index, spawn the traditional haiku grep agent (`~/ai-context-store/*/decisions/` `*/docs/`)
   - (d) conversation-history agent: `{base}/full-combined.txt`
2. Always pass each agent: the regex pattern set / target paths / **limit N (top 15 per pattern, 120-char snippets)** / the temp-file output path `{base}/tmp/search/<run-id>-<role>.txt`. Have each agent run its Grep calls in parallel too.
3. **Judge confidence by agreement of candidates across agents** (if multiple agents surface the same file, that's a strong signal; don't use haiku's self-reported confidence).
4. opus (the main model) Read-verifies the top candidates → integrates them.

### Step 6: Feed back into the lexicon (mandatory on a successful deep path)

When the deep path reaches the right answer, append the expansion that worked as a single line to `{base}/search-lexicon.md`:

```markdown
漂流 ↔ drift, W1, Wasserstein   <!-- found via project search -->
```

This makes **the next fast path deterministically smarter the more you search** (team-shared recall via git).
Always declare whether you appended in the Step 7 report (making omissions visible).

### Step 7: Report format

```markdown
## Search results: {query}

### Related design decisions
1. **{title}** ({date}, score: X.XX)
   - Decision: {summary}
   - File: {base}/decisions/{filename}

### Related research
- {research file}: {summary}

### Conversation history (when the deep path found matches)
- {summary of matched context}

### Notes
- {supersede relations, explicit "not confident", etc.}

### Search method: {fast (ranking vN) / fast+layered (index→timeline→full) / fts5 (store-query.sh, project|all) / deep (haiku xN parallel, wall time Xs) / cross-store: {store names,...}}

### Lexicon: {appended — {the line you appended} / not appended (deep path not run, or failed)}
```

When you are **not confident** (you ended below the threshold), don't fill in with guesses — explicitly state "not confident".

### Handoff to `research` on zero confidence (the store-first closed loop)

When even the deep path ends in **zero confidence** (the store has no answer), it may merely be missing locally while existing externally. If the question requires external information (latest trends / library comparisons / official specs, etc.), propose a handoff to the `research` skill (`/research <query>`). Because `research` in turn "runs `search` (= this skill) first", this forms a closed loop that escalates to the web while preserving the store-first order. If the question is purely about internal history ("what we decided before", "how it came about"), don't hand off — stop at "not confident".

## cross-store NDA / confidentiality

- Keep cross-store search results **as internal references within the session**. Don't transcribe other clients' specifics (project names, decision contents, people) into the current project's deliverables (code, documents, commits) — the write side is enforced by pii-protection / egress-guard.
- Always list which stores you searched in the "Search method" field.

## Data-layer maintenance

- Manual regeneration: `python3 "$CLAUDE_PLUGIN_ROOT/scripts/ai_context_combined.py" --project-root "$PWD" --scope full`
- Temp files under `{base}/tmp/search/` may be deleted once they pile up.
