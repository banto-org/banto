# 並列の自発提案 — fan-out Agent vs worktree

ユーザーが「並行で」と言わなくても、作業が**独立した複数のサブタスクに分割でき、直列依存がない**と判断したら、直列実行せず並列化を**自発提案**する（intent-first の延長 ＝ owner にコマンドを暗記させない）。

## 判断基準

| 条件 | 手段 | 理由 |
|---|---|---|
| 読み取り / 調査 / 分析、または互いに**同一ファイルを触らない**独立編集で、結果を集約するだけ・短命 | **fan-out Agent**（1 メッセージに複数 Agent 呼び出し） | worktree 不要。最も lean（CONCEPT の「built-in agent fan-out」） |
| 並走**ブランチで独立コミット**、長時間、同一ファイル / ビルドが競合、物理分離が要る | **task worktree**（`ws task` / `claude -w`） | git レベルの分離が要る |

## 分割可能性テスト（3 つ全て満たすときだけ提案）

1. サブタスク間に直列依存がない（A の出力を B が待たない）
2. 分割で wall-clock が実際に縮む
3. 統合コスト（マージ / 結果集約）が分割利得を上回らない

迷ったら提案しない（些末・密結合な作業への過剰提案は官僚化 ＝ epic 誤発火と同じ anti-goal）。提案は L2（採用解釈つきで進める）とし、fan-out は即実行可、worktree は構造を作るため軽い確認を挟む。
