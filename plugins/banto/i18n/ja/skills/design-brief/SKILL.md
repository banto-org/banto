# Design Brief — 曖昧な UI 依頼を 14 観点の仕様へ変換する

> 出典: [AI でおしゃれな画面を作るためのデザインシステムを学ぼう！](https://qiita.com/yusuke_ando_vj/items/dd17a285217a15841a3a)（Qiita）。観点の構造だけを借りて再構成した独自版であり、詳細な一覧は原典を参照。

## なぜ要るか

「おしゃれに」「いい感じに」だけの依頼は、AI にもデザイナーにも伝わらない。Web デザインは情報設計・
レイアウト・ビジュアルスタイル・色・文字など複数観点の組み合わせで決まり、**同じサービスでも
ターゲットが変われば正解が変わる**。この skill は曖昧な依頼を、埋めるべき観点が明確なブリーフへ
変換する。

## 手順

1. `references/target-driven-design.md` を読み、ターゲット（人物像・状況・感情）を最初に確定する。
   **ターゲットが埋まらないうちは他の観点へ進まない** — 全観点がここから波及するため。
2. `references/brief-template.md` の 14 観点を順に埋める。プレーンテキストの対話で、ユーザーの
   生の言葉を拾う（AskUserQuestion は使わない）。
3. ビジュアルスタイルを選ぶ段階では `references/style-catalog.md` の代表スタイルから、単体でなく
   組み合わせで指定する。
4. 埋め終えたブリーフを会話内に提示する。実装や画面生成へ進む場合は `/spec` へ引き継ぐ（コード生成
   そのものはこの skill の範囲外）。

## 原則

- ターゲット優先：色・文字サイズ・トーン・スタイルはすべてターゲットから波及して決まる（詳細は
  `references/target-driven-design.md`）。
- 希望する印象だけでなく、避けたい印象も必ず併記する。
- 受け手レベル（L1-L3、文章の読みやすさ軸）とターゲット（デザインの見た目軸）は独立の軸として扱い、
  混同しない。

## 禁止

- ターゲット未確定のままレイアウト・色・スタイルを決める。
- 14 観点を絞らず、まとめて曖昧に流す。
