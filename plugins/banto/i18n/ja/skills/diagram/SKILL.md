# diagram — 図種の選択と実務パターン

レンダ手順（mermaid / draw.io 経由の SVG 化・テーマ・埋め込み）は `references/render-pipeline.md` が
持つ。本文はその手前、**伝えたい構造からどの図種を選び、どう崩さず書くか**に特化する。
手順の再掲はしない。

## references の選び方

- 説明図（概念・構造を伝える図）→ `references/svg-patterns.md`（14 パターンの完全 SVG コード集。
  複製してテキスト・色・座標を差し替える）
- シーケンス図・状態遷移図・依存関係つきガントの自動生成 → `references/mermaid.md`
- AWS 構成図（VPC / サブネット / AZ の入れ子・アイコンセット）→ `references/drawio-aws.md`
- .mmd / .drawio を SVG 化して資料へ埋め込む手順 → `references/render-pipeline.md`

説明図はまず svg-patterns.md の 14 種から選ぶ。判断分岐が多い厳密なフローや、要素数が各パターンの
上限を超える図だけ mermaid の自動レイアウトへ切り替える。

## 選択表（伝えたい構造 → パターン）

| 伝えたい構造 | パターン |
|---|---|
| 2 つのリストの 1 対 1 対応（問題→対策、要件→機能） | ① 対応マッピング図 |
| 良い/悪い・Before/After・因果の左右対比 | ② ✗/✓比較図 |
| 有限の容量・構成比の変化（削ると空く） | ③ 容量・積み木図 |
| 手順・プロセスの流れ（戻り分岐 1 本まで） | ④ 連鎖・フロー図 |
| 序列・ランキング・大小 | ⑤ ランキング横棒 |
| 結論を頂点にした説得の階層（提案・報告） | ⑥ ピラミッドストラクチャー |
| 分解・階層（モレなくダブりなく。問題分析） | ⑦ ロジックツリー |
| 2 論点でのポジショニング・優先づけ | ⑧ 2軸マトリクス |
| 集合の重なり・共通項（3C 等） | ⑨ ベン図 |
| 循環するプロセス（PDCA 等） | ⑩ サイクル図 |
| タスク × 期間のスケジュール（現場レベル） | ⑪ ガントチャート |
| 段階を経て数が絞り込まれるプロセス | ⑫ ファネル図 |
| 時間軸 × 取り組みカテゴリの全体計画 | ⑬ ロードマップ |
| 部門・担当者をまたぐ業務プロセス（誰が・いつ） | ⑭ スイムレーン |

似た構造の使い分け: 説得が目的なら ⑥ ピラミッド、分解・発見が目的なら ⑦ ロジックツリー。
全体計画は ⑬ ロードマップ、週次の詳細工程は ⑪ ガント。未来の戦略立案は ⑧ マトリクス、
既存データの分布・相関は散布図（実データのグラフ）。

表にない構造は図種を変える。割合・内訳（円グラフ・積み上げ棒）、時系列推移（折れ線）、
分布・相関（散布図）など実データのグラフはチャートライブラリで描く。API 呼び出しの時系列は
mermaid `sequenceDiagram`、状態遷移は `stateDiagram-v2`（mermaid.md 参照）。

## 設計原則（全図種共通・5 項）

1. **1 図 1 メッセージ** — 伝えたいことを 1 つ決めてから図種を選ぶ。詰め込むと主メッセージが埋もれる。
2. **ラベルは要素の隣** — 凡例（色と名前の対応表）に分離しない。視線の往復が理解を落とす。
3. **強調は 1 属性だけ** — 色・太さ・大きさのうち 1 つだけ変える。複数同時に変えると探索が遅くなる。
4. **装飾ゼロ** — グラデーション・影・3D・無関係なアイコンは使わない。データを表さないインクは削る。
5. **キャプションに結論** — figcaption に「この図が言いたい 1 文」を書く。図の内容の繰り返しは書かない。

## 数値制約の総則（手描き SVG）

- `viewBox="0 0 624 高さ"` 固定。`width` / `height` 属性は付けない
- 座標は 8px グリッドに整列。箱の高さは 40 / 48 / 56px に統一し、幅だけ内容で変える
- **箱の幅 = ラベル上限文字数 × 13px + 余白 24px** を最低幅とし、8 の倍数へ切り上げる
- 文字は 11px 以上（本文ラベル 12〜13px / 見出し 13〜14px）。改行は `tspan` の手動改行のみ
- 矢印は `<defs><marker>` 1 種類を使い回す。`role="img"` + `aria-label` を必ず付ける
- 各パターンの要素数・文字数上限（svg-patterns.md に個別記載）を超えたら、詰めずに図を分割する

## 共通原則

- レンダ手順は `references/render-pipeline.md`、カラートークンは docs skill の theme-default.md
  （theme-custom.md があればそちら）を正本とする。svg-patterns.md の説明図も同テーマのトークンを
  使い、新色を発明しない。
- 出力は `<figure>` + SVG + `<figcaption>`（結論 1 文）のセットで渡す。
