# Mermaid の実務パターン

既存 html-doc skill の diagrams.md は、テーマヘッダの書き方・`render-diagram.sh` によるレンダ手順・SVG インライン埋め込みの一連の流れを扱う。本ガイドはその手前、記法そのものの実務パターンに特化する。レンダ手順は diagrams.md を参照し、ここでは再掲しない。

## 図の種類を選ぶ基準

やり取りや API 呼び出しの時系列を示すなら `sequenceDiagram` を第一候補にする。処理の分岐や意思決定を示すなら `flowchart`、状態の遷移（申請中 → 承認済み → 却下、のような有限状態）を示すなら `stateDiagram-v2`、日程を示すなら `gantt` を選ぶ。4 つの記法の使い分けを誤ると、読み手が本来読み取るべき軸（時系列か、分岐か、状態か）を見失う。

| 示したいこと | 記法 | 誤用の典型 |
|---|---|---|
| API 呼び出し・やり取りの順序 | `sequenceDiagram` | flowchart で書き、矢印だけで順序を表現しようとして矢印が交錯する |
| 条件分岐・処理の流れ | `flowchart LR`（横基本） | stateDiagram で書き、遷移条件をラベルに詰め込みすぎる |
| 状態と遷移条件 | `stateDiagram-v2` | flowchart の矢印ラベルで代用し、初期状態・終了状態が図に現れない |
| 日程・マイルストーン | `gantt` | 表で十分な内容まで gantt 化し、依存関係のない棒だけが並ぶ |

## シーケンス図の実務パターン

参加者は登場順に `participant` で明示し、mermaid の自動並べ替えに任せない。エイリアスを使うと日本語ラベルが折り返れるため必ず付ける。

```
sequenceDiagram
  participant U as 利用者
  participant W as Web サーバ
  participant D as DB

  U->>W: 申請を送信
  activate W
  W->>D: 申請データを保存
  D-->>W: 保存完了
  W-->>U: 受付番号を返す
  deactivate W

  Note over U,W: ここまでが一次受付
```

同期呼び出しは `->>`、応答は `-->>` を使い分ける。`activate`/`deactivate` は処理中の帯を出すが、参加者が 4 人を超える図では帯が重なって読みにくくなるため、複雑な図では省略する。

## flowchart / state / gantt の使い分けの補足

flowchart は `LR`（左→右）を既定にし、分岐が深い場合のみ `TD`（上→下）に切り替える。stateDiagram-v2 では開始・終了を必ず `[*]` で明示する。

```
stateDiagram-v2
  [*] --> 申請中
  申請中 --> 承認済み: 承認
  申請中 --> 却下: 却下
  承認済み --> [*]
  却下 --> [*]
```

gantt は依存関係（`after`）がある工程だけを対象にする。依存のない並行タスクを gantt で並べても情報量は表と変わらないため、その場合は表を使う。

## 日本語ラベルの注意

ラベルが 12 文字を超える場合、mermaid のノード幅が自動計算されず文字がはみ出す。`<br/>` で手動改行を入れる。

```
A[申請内容の<br/>一次確認]
```

全角括弧 `（）` はノードラベル内でパーサに解釈されずそのまま通るが、`[]` `{}` `()` の半角記号はノード形状の指定と衝突するため、ラベル文中では使わない。使う場合はラベル全体をダブルクォートで囲む。

```
A["係数（0.8）を適用"]
```

## 破綻しやすい構文

`subgraph` を 3 階層以上ネストすると、レイアウトエンジンが崩れて要素が重なる。ネストは 2 階層までに抑え、それ以上必要な図は分割する。

```
subgraph 本番環境
  subgraph Web層
    A[サーバ1]
    B[サーバ2]
  end
end
```

ノード ID に日本語や記号（`-` `.` `/`）を使うとパースエラーになる。ID は英数字とアンダースコアのみにし、日本語はラベル側に書く。

```
web_1[申請受付サーバ]   // 良い例: ID は英数字、ラベルは日本語
申請サーバ1[申請受付]   // 悪い例: ID に日本語 → パースエラーの原因
```

コロン `:` はエッジラベルの区切り文字と衝突するため、ノードラベル内では避けるか引用符で囲む。

## レビューしやすい .mmd 分離管理

図 1 つにつき `.mmd` ファイルを 1 つ切り出し、資料本体とは別に diff レビューできる状態にする。ファイル名は図の内容が分かる英語スラグにし、資料と同じディレクトリに置く（例: `docs/report/flow-approval.mmd`）。レンダ後の SVG はコミット対象にしても、`.mmd` を消さない — 改訂のたびに手で SVG を描き直す事故を防ぐ。

## 良い例・悪い例

良い例は、参加者・ノード ID が英数字、ラベルが日本語、テーマヘッダが資料のトーンに揃っている図。悪い例は、次のいずれかを含む図。

- subgraph 4 階層のネストで要素同士が重なっている
- ノードラベルが 20 文字を超え、`<br/>` の改行なしにはみ出している
- 依存関係のない 3 タスクを gantt で無理やり横棒にしている（表で足りる内容）
- デフォルトの紫テーマのまま資料に貼っている（diagrams.md のテーマヘッダ未適用）

## セルフチェック

- 図の種類（シーケンス/フロー/状態/ガント）が示したい軸と一致しているか
- ノード ID が英数字のみ、ラベルが日本語で 12 文字超は `<br/>` 改行済みか
- subgraph のネストが 2 階層以内か
- `.mmd` を資料と同じ場所に併納し、SVG と両方コミットしているか
- テーマヘッダで資料の配色と揃っているか（diagrams.md 参照）
