# shared-rules ― 全形式横断のルール（引用・用語・テーマ・図・検証）

## 引用・出典のルール

分類の基準は**情報の在り処ではなく、主張の権威（根拠）の出所**。

- **出典不要**: ユーザー自身の内部データ、会話で渡された事実そのもの（売上数値、社内の決定事項など）。必要ならファイル名程度の言及でよい
- **出典必須**: 主張の根拠が**外部起源**のもの ― 研究・統計・規格・書籍・他社事例。**PC内のファイルに転記されていても、外部起源なら出典必須**（原典を辿って確認する）
- 判定例: 素材ファイルに「○○大学の研究では…」とあれば、それは外部情報。ファイル内にあることは出典免除の理由にならない
- 出典URLは確認してから書く。確認できない外部主張は書かない
- **リンク先の主張一致**: URLの到達確認だけでなく、リンク先がその主張を実際に裏付けているかを確認する（例: 「今年の単語に選出」の出典に測定論文を貼らない。主張ごとに正しい原典へ）
- 記載位置: 数値・研究・規格は主張の直後（HTML=リンク、pptx/docx=脚注・欄外、xlsx=注記）
- **密度の上限**: 出典は1文に最大2個。3個以上並ぶ場合は代表1つを本文に残し、残りは巻末の出典一覧へ回す（リンクの団子は読みの流れを切る）
- **ラベルの統一**: リンクラベルは「著者名 年↗」（例: Cowan 2010↗）。著者が立たない場合は「媒体名 年↗」（例: 文化庁 2022↗）。「実験研究↗」「メタ分析↗」のような種別ラベルは使わない

## 用語スイープ（省略禁止）

業界の人や英語話者でないと分からない語が注釈なしで残ることが、最頻の品質事故。

1. **抽出**: `scripts/term-sweep.py 生成物 --known <生成物名>.known-terms.txt` を実行し、カタカナ語・英単語・略語を機械的に列挙する（known ファイルの置き場所は表現スイープ節の標準と同じ）
2. **判定**: 想定読者が説明なしで分かる語か1語ずつ判定。**読者が未指定なら一般読者を既定とし、迷った語はすべて「分からない」側に倒す**（注釈は多い分には引っ掛かりにならない）
3. **注釈**: 分からない語は**初出に1回**注釈。手段は形式別リファレンスの「用語注釈」節に従う（正典は各 format 側。ここでは列挙しない）
4. **再確認**: 頻出語（5回以上）は注釈済みでも用語集に必ず収録。英語由来のツール名・概念名（skill、hook、トークン等）も注釈対象。「開発者なら分かる」は禁句
5. **用語集の質**: 見出し語には英語原語を併記する（例: ワーキングメモリ working memory）。本文を平易化して正式名を外した場合でも（例: BLUFを「結論を最初に書く型」と言い換えた場合）、**正式名は用語集に必ず残す** ― 平易化は本文の義務、正式名の保存は用語集の義務
6. **完了判定**: term-sweep.pyを再実行し、未注釈語ゼロ（または判定済み除外リスト付き）を確認する

## テーマ解決ルール（色・デザインの差し替え）

1. references/ フォルダに `theme-custom.md` が**存在すればそれを使う**（会社・個人のテーマ。全トークンを上書き）
2. 存在しなければ `references/theme-default.md` を使う
3. ユーザーが会話でテーマ指定したら、theme-custom.mdとして保存してから使う（次回以降も効く）

テーマで変えてよいのは色・フォント・ロゴ類のみ。本文やレイアウト構造は変えない。

## 図のルール

- 対比・対応・流れ・階層・序列の説明が文章で3行を超えたら図にする。パターンは diagram skill
- **図中は平易語を使う**: 図のラベルには専門語を入れず平易な言い換えを置く（「外在的負荷」→「伝え方の負荷」、「MECE」→「重複と漏れなく」）。専門語の正確な名称と説明は本文側のツールチップ・注釈が担う。図は1メッセージの平易さを、本文は正確さを受け持つ分担
- 変換: HTML=SVGのまま埋め込み／pptx・xlsx・docx=SVGをPNGに変換（300dpi相当・透過。手順は各format）
- **表示チェック必須**: 生成物を開くかレンダリングし、(a)文字のはみ出し (b)図の欠け・崩れ (c)ラベルの重なり を確認。確認せずに納品しない

## 表現スイープ（省略禁止）

硬い・翻訳調・AI っぽい表現（「されうる」「することができる」「において」等）が残ることが、
用語の未注釈に次ぐ品質事故。言い換えの正典は `references/wording-swaps.md`。

0. **除外ファイルの標準**: 生成物と同じディレクトリに `<生成物名>.known-terms.txt`（用語）と
   `<生成物名>.known-style.txt`（表現）を置き、生成物と一緒に残す（判定の記録。初回は空で作る）
1. **検出**: `scripts/style-sweep.py 生成物 --known <生成物名>.known-style.txt` を実行し、検出行を列挙する
2. **判定**: 1 件ずつ「言い換える」か「意図的に残す」かを判定。残す場合（法令調・引用など）は
   除外ファイルに文脈断片を登録する（判定の記録になる）
3. **完了判定**: 再実行して検出ゼロ（または全件除外登録済み）を確認する

## 共通検証（各形式の検証に加えて）

1. `scripts/term-sweep.py` で未注釈語ゼロを確認（HTMLは `scripts/verify-html.py` も実行）
2. `scripts/style-sweep.py` で硬い表現・文体混在の検出ゼロを確認（上の表現スイープ手順）
3. 外部起源の主張への出典付与、内部情報への不要な出典がないこと
4. 図の表示チェック完了
5. 引っ掛かりセルフチェック: 知らない人のつもりで通読し、(a)検索したくなった語 (b)疑った主張 (c)二度読みした箇所 に印。印ゼロまで直す
