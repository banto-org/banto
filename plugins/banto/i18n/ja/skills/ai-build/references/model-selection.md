# 手法選定 + モデル選定ガイド

Stage 4 の補助。**手法（prompt / RAG / fine-tune）をまず決め、その上でモデルを選ぶ**。Claude の具体的な id・価格・コンテキスト窓・パラメータは陳腐化が速いため、本ファイルに**焼き込まず** `claude-api` skill に委譲する（記憶で答えない）。

## 手法選定（prompt / RAG / fine-tune）

「最小で済む方から試す」が原則。prompt で足りるなら RAG を足さない。RAG で足りるなら fine-tune しない。

| 手法 | 向く課題 | 向かない課題 | コスト / 手間 |
|---|---|---|---|
| **プロンプトのみ** | 汎用タスク（要約 / 分類 / 抽出 / 書き換え / 会話）。知識がモデル内 or 文脈に収まる | 大量の私有 / 最新知識が要る・厳密な様式の大量再現 | 最小（即反復） |
| **RAG**（検索 + 文脈注入） | 私有文書 / 最新情報に根拠を持たせる・出典提示・知識が頻繁に更新される | 推論様式そのものを変えたい・検索で拾えない暗黙知 | 中（検索基盤 + チャンク設計） |
| **fine-tune** | 固定様式の大量再現・遅延 / コスト削減のための小型化・特殊ドメイン語彙 | 知識を足したいだけ（→ RAG）・要件が流動的 | 大（データ整備 + 学習 + 再学習運用） |

判断の目安:
- まず **プロンプト**で成功基準に届くか試す（few-shot / CoT / 構造化出力）。
- 私有 / 最新知識への**根拠**が要る → **RAG**。
- 様式の厳密再現 or 規模での**コスト / 遅延**が問題で、データが用意できる → **fine-tune**。
- 併用可（RAG + 少数ショット、fine-tune した小型 + RAG など）。

## プロンプト設計の型

- **few-shot**: 入出力例を 2〜5 個。様式・トーン・境界例を見せる。
- **chain-of-thought**: 段階推論を促す（最終出力と思考を分離して取り出す）。
- **構造化出力**: JSON スキーマ / tool use で機械可読に固定（パース失敗を eval の format 軸で検出）。
- 詳細・最新の機能（prompt caching / tool use / extended thinking 等）は `claude-api` skill。

## RAG 設計の勘所

| 要素 | 決めること |
|---|---|
| チャンク | サイズ / オーバーラップ / 境界（見出し単位など） |
| 埋め込み | モデル選定（次元・コスト・多言語対応） |
| 検索 | top-k・ハイブリッド（BM25 + ベクトル）・リランク要否 |
| 注入 | 文脈窓に収める件数・出典の付け方 |

RAG は eval で **faithfulness（根拠に忠実か）/ relevance（検索が的確か）** を測る（[`eval.md`](eval.md)）。

## モデル選定

軸は **用途品質 / コスト / レイテンシ / コンテキスト窓**。具体的な選択肢（id・価格・窓・各モデルの得意領域）は **`claude-api` skill を読む**（本 skill は id を持たない）。一般則のみ:

- 難しい推論 / エージェント的多段タスク → 上位モデル。
- 大量 / 単純 / 低レイテンシ要件 → 小型・高速モデル。
- まず上位で品質を作り、eval が通る範囲で**小型へ落としてコスト最適化**する（eval が安全網）。
- 他プロバイダ（OpenAI / Gemini 等）が対象なら claude-api はスキップし、そのプロバイダの一次情報を research で取る。

## 決定記録

選んだ手法 / モデル / その根拠を `{base}/decisions/` に残す（`ai-context`）。eval 前は `status: provisional`、eval で裏が取れたら `accepted`。後でモデルを差し替えるとき、過去の選定根拠と eval スコアが比較材料になる。
