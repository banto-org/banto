# PII / 内部名保護ルール

プロジェクト横断の機密保持（NDA / 契約）に関する行動規範。シークレット保護（`safety.md`）の姉妹ルール。
決定論的な強制は `egress-guard.sh`（PreToolUse Write/Edit）が担う。

## 原則

- **内部メンバー名・他プロジェクト名・他社の識別情報・PII を、クライアント成果物（クライアントリポジトリ / 引き渡し成果物）へ絶対に書かない。** 必要に応じて一般名詞でマスクする（例: 「担当者A」「〇〇社」「関係者」）。
- **プロジェクト間でコンテキストを持ち越さない。** クライアント A の決定・ドキュメント・関係者名を、クライアント B のセッションや成果物へ混ぜない。
- ai-context（`.ai-context/` / 中央 store）に内部名が存在すること自体は問題ない。問題は **クライアントへの egress**。この 2 つは分けて扱う。

## マスク対象の例

| 種別 | 例 | クライアント成果物での扱い |
|---|---|---|
| 内部メンバー名 | 同僚のフルネーム | マスク（「担当者A」等） |
| 他プロジェクト / 会社名 | 他クライアントの社名やコードネーム | 書かない |
| PII | メール / 電話 / 住所 / 個人 ID | マスクまたは削除 |
| 自社の機微情報 | 内部の契約条件・単価 | クライアント向けには書かない |

## 仕組み（強制）

- **名前レジストリ**: `~/.claude/banto-name-registry`（ユーザースコープ、1 行 1 名 / `re:` 正規表現）。**リポジトリ / store へ絶対にコミットしない**（名前リスト自体が漏れるため）。
- **egress-guard**（`egress-guard.sh`、PreToolUse Write/Edit）は、レジストリの名前に一致する書き込みをクライアントパスへ行おうとすると **ブロックする**。正当な理由があるときのみ `BANTO_ALLOW_NAMES=1` でエスケープする。レジストリが存在しない場合 / python3 がない場合は no-op。除外パス + チューニング（`BANTO_EGRESS_SAFE_PATHS`）はスクリプト内にある。

## 禁止事項

- 内部名 / 他プロジェクト名 / PII を **マスクせずに** クライアント成果物へ書くこと
- 理由なく `BANTO_ALLOW_NAMES=1` でガードを恒久的に無効化すること
- 名前レジストリをリポジトリ / 中央 store へコミットすること
