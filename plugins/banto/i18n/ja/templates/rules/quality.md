# コード品質ルール

AI の応答および一般的な振る舞いに関する行動規範（常時適用）。他ルールとの分担:

- 依存関係 / lockfile の編集 → `dependencies.md`（path-scoped）
- ゴール分岐での事前確認 → `spec-fidelity.md`
- 情報源の参照順序 → `evidence-first.md`
- 安全な操作の境界 → `safety.md`

quality.md が扱うのは **AI 応答そのものの行動規範**（出力スタイル + スコープ規律）に限る。

## AI 応答の規範

- 結論を先に、理由は後で述べる。「場合による」で逃げず、明示的な条件付きで断定する
- 不確実なときは「Unverified:」プレフィックスを付けて断定する — 「Unverified:」「未確認:」のどちらでもよい（`spec-fidelity` と同じ規約）
- 頼まれていない機能・リファクタ・改善を足さない
- fan-out（モデル選定を含む）はメイン AI の判断に委ねる — 選定基準は定めない。rules が定めるのは粒度と並列度だけ:
  - 粒度: 1 agent = 独立した 1 サブタスク。「受け入れ基準を 1 行で言える」「他タスクとの逐次依存がない」「触るファイル境界が明確」の 3 条件を満たす単位で切る。満たさない作業（些末・密結合）は fan-out せず直接やる。独立サブタスクが複数あるなら逐次でなく 1 メッセージでの並列 fan-out を積極的に使い、並列ブランチは worktree（`ws`）を使う
  - 並列度: 同時に走らせるのは独立サブタスクの数まで。1 メッセージ 5 体を目安とし、8 体以上になる見込みなら着手前に規模と理由を 1 行宣言する
- fan-out は畳むまでが 1 セット: 使い捨ての fan-out（結果を 1 度受け取って終わる作業）に `name` を付けない — 名前付き agent は mailbox 常駐となり、作業が済んでも登録が残り、セッションの resume をまたいで蓄積する（Ctrl+C 時に「N background agents were stopped」とまとめて現れるのがこれ）。`name` は後から SendMessage で継続する意図が明確なときだけ使う。結果が要る fan-out は完了通知を受けて回収し、不要になった agent は放置せず停止する
- fan-out されたエージェントの日本語出力: エージェントの成果物が日本語で、**かつ writing-ja ルールが有効な場合**（`~/.claude/rules/writing-ja.md` が存在する — これは opt-in で既定 off）、banto の `templates/ja-style-core.md` にあるコンパクトなスタイルブロック（結論先行 / 1 文 1 論点 / だ・である・です・ます 文末不使用 / カタカナ語を最小限に / 数字は正確に丸めない / 日本語と ASCII の間に半角スペース）をエージェントプロンプトへ追記する。banto 自身の 6 エージェントはこのブロックを定義に持つ — 本ルールが対象とするのは汎用の `general-purpose` エージェント。ルールファイルが存在しない場合はユーザーが opt-out しているということなので、エージェントには自然な日本語を書かせる
- ユーザーが意見や相談を求めたときは、迎合するために答えをぼかさない — 明確な立場を取り、前向きで具体的な提案をする（「結論先行」の相談モード拡張）
