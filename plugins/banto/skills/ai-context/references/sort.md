# /ai-context sort — routing detail (internal + project-wide, the former doc-sort merged in)

Two modes, switched by argument:

| Invocation | Mode | Target |
|---|---|---|
| `/ai-context sort` | **Internal mode** (default) | Sort misplaced files inside `{base}/` |
| `/ai-context sort project` | **Project-wide mode** (former doc-sort) | Tidy documents scattered at the repo root / under `docs/` etc. |

Natural language such as "tidy up the docs", "things are a mess", or "move the docs" also fires ai-context, and the mode is judged from context (if it sounds project-wide, use project mode).

---

## Internal mode (default)

### Purpose
**Interactively sort** misplaced files inside `{base}/` (the ones doctor detected). Nothing is moved without user approval.

> store-first: BASE resolution is as described at the top of SKILL.md. The `{base}/` below refers to the resolved base. The canonical source for bucket names and prefix definitions is [`directory-structure.md`](directory-structure.md).

### Steps

1. Internally re-run the doctor diagnosis (no writes)
2. Classify the move candidates and present them:

```
## {base}/ routing candidates

### [Prefix violation] directly under docs/
| # | File | Recommended action | Reason |
|---|---------|--------------|------|
| 1 | docs/meeting-notes.md | rename to `[Memo] meeting-notes.md` | meeting-notes type |
| 2 | docs/api-review.md | rename to `[Review] api-review.md` | review type |

### [Missing date] decisions/
| # | File | Recommended action |
|---|---------|--------------|
| 4 | decisions/old-decision.md | rename to YYYY-MM-DD-HHMMSS_old-decision_<user>.md |

### [Stale session] sessions/
| # | File | Updated | Recommended action |
|---|---------|--------|--------------|
| 5 | checkpoint-2026-03-01-1430.md | 46 days ago | delete |
```

3. Ask the user to choose:

```
Specify by number:
- run all → "all"
- confirm each one → "each"
- specify numbers → "1,3,4"
- abort → "skip"
```

4. When executing, **prefer `git mv` where available**, otherwise `mv`. Confirm before any `rm` deletion.

5. After completion, the search-side `combined.txt` is automatically regenerated by a hook (`ai-context-combined-rebuild.sh`) on save, so no manual operation is needed.

6. Completion report:

```
## Routing complete

- Renamed: N
- Moved: N
- Deleted: N
- Skipped: N

Recommended: check the final state with `/ai-context doctor`
```

## Safety rules (internal mode)

- **As a rule, do not touch dated files inside `decisions/`** (already canonical)
- Do not touch files inside `docs/research/` (research-agent output is free-form, which is fine)
- Do not move conventional files such as `README.md` / `LICENSE`
- Under `git` control, warn if `git status` shows staged changes

---

## Project-wide mode (`/ai-context sort project`, the former doc-sort)

Interactively tidy documents scattered across the project. The target is everything outside `{base}/` (the store-side ai-context base) — files at the repo root, under `docs/`, etc.

### Target file types
```
.md, .txt, .rst, .docx, .doc, .pptx, .xlsx, .xls, .csv, .tsv, .pdf
```
In addition, `.json .yaml .yml .toml` are scanned too, but **config files (package.json / tsconfig.json / pyproject.toml etc.) are skipped**, while documents (openapi.yaml / api-spec.json etc.) are included.

### Excluded directories
```
node_modules, .git, dist, build, .next, .nuxt, __pycache__,
.ai-context/sessions,
vendor, target, .venv, venv
```

### Steps

**Step 1: Scan**
- Small (~50 files or fewer): run `Glob` per extension in the main session
- Medium to large (over 50 / monorepo): delegate to an `Explore` subagent (prevents a flood of paths into the parent context). When in doubt, lean toward Explore.

**Step 2: Classify** — present to the user in 3 categories:
- `[Move recommended]` sitting at the repo root → recommend moving into `docs/` (# / file / size / suggested destination / action)
- `[Reference only]` cannot be moved (README / LICENSE / CHANGELOG / CONTRIBUTING / CODE_OF_CONDUCT / anything under `.github/` / sub-package READMEs)
- `[Confirm]` needs a judgment call (move to docs/ / delete / leave as is)

**Step 3: Dialogue** — ask for a choice via `1,2` / `all` / `each` / `skip`.

**Step 4: Execute** — prefer `git mv` (otherwise `mv`). Create `docs/` if it does not exist.

**Step 5: Propose search registration** — if `docs/` etc. is not yet registered in `config.json`'s `extra_docs_dirs`, propose registering it → on yes, add it to `extra_docs_dirs` (it gets reflected into `combined.txt` on the next hook regeneration; no manual rebuild needed).

**Step 6: Generate the reference index** — save an index of all documents to `{base}/docs/[Index] project-documents.md` (3 tables: docs/ / root (non-movable) / sub-packages).

**Step 7: Completion report** — a summary of moved / skipped / deleted / search-registered (`extra_docs_dirs` added).
