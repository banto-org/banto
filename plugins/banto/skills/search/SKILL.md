# Search — internal search (Claude-native)

> **Search base (store-first)**: in this skill, `{base}` refers to the ai-context base. Search under the absolute path that the SessionStart/PreCompact hook injects as "ai-context base: &lt;absolute path&gt;" (resolve it with `sh "$CLAUDE_PLUGIN_ROOT/scripts/_ai-context-paths.sh" --resolve "$PWD"` when unknown).

When the user is conversing in Japanese, respond in Japanese (write the search report in Japanese too).

## search vs research

| | `/search` (this skill) | `/research` |
|---|---|---|
| Target | **Internal**: `{base}/decisions/` `docs/` + conversation history + `extra_docs_dirs` | **External**: the web, GitHub, arxiv, X, official docs |
| Web access | **None** | Yes (WebSearch + research-agent) |
| Result | references / summaries of existing files | new files saved under `{base}/docs/research/` |
| Latency | fast: seconds / deep: minutes | minutes (parallel launch of research-agent) |

**Mnemonic**: do you already have it or not. Have it → `search`, don't have it → `research`.

## Search targets and data layers

| Path | Content | Freshness |
|---|---|---|
| `{base}/decisions/` `{base}/docs/` | design decisions, reports, research | search the raw files directly |
| `{base}/project-combined.txt` | the above concatenated into one text | auto-regenerated by a hook on save (ai-context-combined-rebuild.sh) |
| `{base}/full-combined.txt` + `sessions-cache/` | + conversation history (including content lost to compaction) | updated on demand at search time (see the deep path below) |
| `{base}/search-lexicon.md` | **search lexicon** (concept ↔ translation / synonym / abbreviation) | appended on deep-path success (see below) |
| the project's `docs/` `specs/` etc. | added via `extra_docs_dirs` in `{base}/config.json` | included in combined generation |

## Search procedure

### Step 0: Read the lexicon

If `{base}/search-lexicon.md` exists, Read it and pull the terms from matching lines into the expansion (skip if absent).

### Step 1: Query expansion (3 tiers, weighted)

Expand the query into **weighted groups** by the following rules:

1. **Tier1 (×1.0) = synonyms**: put Japanese synonyms + **English translations** + katakana spelling variants + abbreviations into the same group (always assume records might be in English; "漂流" → drift).
2. **Tier2 (×0.6) = near concepts**
3. **Tier3 (×0.3) = adjacent concepts**: put "similar but differently intended" terms here (monitoring → audit). Catch them, but don't let them dominate.
4. **Decompose interrogatives**: "why was X deprecated" → make `[X]` and `[廃止|supersede|撤廃]` **separate Tier1 groups** (the multi-group-match bonus acts as a soft-AND).
5. **Split compound terms**: "ProjectX 漂流" → `[ProjectX]` + `[漂流|drift]`
6. Short ASCII tokens (PR/WS/KD) can be passed as-is (the script adds `\b` boundaries).

### Step 2: fast path (default, seconds)

Score with the ranking script:

```bash
python3 "$CLAUDE_PLUGIN_ROOT/scripts/ai_context_search_rank.py" \
  --base "{base}" --top 8 \
  --groups '[[1.0,["認証","auth","OAuth"]],[0.6,["認可"]],[0.3,["ログイン"]]]'
```

- Treat `confident: false` in the output JSON (top score < 1.0) as **zero hits** → go to Step 4
- `confident: true` → go to Step 3

### Step 3: Verify (Read and judge)

Read the top 3–5 files and **judge relevance yourself**:

- Exclude polysemy mismatches (e.g., a doc where "harness" means a wiring harness).
- Exclude self-references (the very document you're writing now, an evaluation table that merely quotes the query).
- Check supersede relations (has an old decision been overwritten by a newer one?).

### Step 4: Second pass on zero hits (once only)

Redo Steps 1–2 with a different synonym set (flip the translation direction, expand abbreviations to full names, change the splitting granularity). If still `confident: false` → escalate to the deep path in Step 5.

### Step 5: deep path (parallel haiku, minutes)

**Triggers**: still zero hits after the second pass / "thoroughly", "everything" / "in another project" (cross-store) / "what we talked about earlier" (conversation history). History and cross-store queries **may start here**, skipping fast.

0. Record the start time (report wall-clock time). For history search, first update full-combined:
   ```bash
   python3 "$CLAUDE_PLUGIN_ROOT/scripts/ai_context_combined.py" --project-root "$PWD" --scope full
   ```
1. **Launch 3–5 `search-agent`s (model=haiku) in parallel within a single message**. Standard division of labor:
   - (a) Japanese spelling-variant agent: `{base}/decisions/` `{base}/docs/`
   - (b) English / code-term agent: the same paths
   - (c) cross-store agent: `~/ai-context-store/*/decisions/` `*/docs/` (grep the store roots directly)
   - (d) conversation-history agent: `{base}/full-combined.txt`
2. Always pass each agent: the regex pattern set / target paths / **limit N (top 15 per pattern, 120-char snippets)** / the temp-file output path `{base}/tmp/search/<run-id>-<role>.txt`. Have each agent run Grep in parallel too.
3. **Judge confidence by agreement of candidates across agents** (if multiple agents surface the same file, that's a strong signal; don't use haiku's self-reported confidence).
4. opus (the main session) Read-verifies the top candidates → integrates.

### Step 6: Feed back into the lexicon (mandatory on deep-path success)

When the deep path reaches the right answer, append the expansion that worked as one line to `{base}/search-lexicon.md`:

```markdown
漂流 ↔ drift, W1, Wasserstein   <!-- found via project search -->
```

This makes **the next fast path deterministically smarter the more you search** (team-shared recall via git).

### Step 7: Report format

```markdown
## Search results: {query}

### Related design decisions
1. **{title}** ({date}, score: X.XX)
   - Decision: {summary}
   - File: {base}/decisions/{filename}

### Related research
- {research file}: {summary}

### Conversation history (when the deep path found matches)
- {summary of matched context}

### Notes
- {supersede relations, explicit "not confident", etc.}

### Search method: {fast (ranking vN) / deep (haiku xN parallel, wall time Xs) / cross-store: {store names,...}}
```

When **not confident** (you finished below the threshold), don't fill in guesses — state "not confident" explicitly.

### Handing off to `research` on zero confidence (the store-first closed loop)

If you exhaust even the deep path and finish at **zero confidence** (the store has no answer), it may simply be absent locally yet present externally. If the question requires external information (latest developments / library comparisons / official specs, etc.), propose handing off to the `research` skill (`/research <query>`). In reverse, `research` "first runs `search` (= this skill)", so this forms a closed loop that escalates to the web while preserving the store-first order. If the question purely asks about internal history ("what we decided before", "the backstory"), don't hand off — stop at "not confident".

## cross-store NDA / confidentiality

- Keep cross-store search results **as internal references within the session**. Don't transcribe other clients' specifics (project names, decision content, people) into the current project's deliverables (code, docs, commits) — on the write side, pii-protection / egress-guard enforce this.
- Always list which stores you searched in the "Search method" field.

## Data-layer maintenance

- `project-combined.txt` is auto-regenerated by a hook on writes to decisions/docs (millisecond scale, no model needed).
- Manual regeneration: `python3 "$CLAUDE_PLUGIN_ROOT/scripts/ai_context_combined.py" --project-root "$PWD" --scope all`
- Temp files under `{base}/tmp/search/` can be deleted once they pile up.
