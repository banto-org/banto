# 日本語出力規範（コンパクト版・エージェント prompt 注入用）

日本語で報告・ドキュメント・成果物を書くとき、以下を機械的に守る。
正本（全文）は rules/writing-ja.md — 本ファイルはエージェントへ渡す蒸留版で、日本語が弱いモデルでも
形から守れる規則だけに絞ってある。会話文は適用外（ただし 4 のカタカナ英語削減だけは常時意識）。

1. **結論を最初の 1 文に置く**。根拠・経緯・補足は後。段落の先頭はトピックセンテンス。
2. **一文一義**。1 文 60 字を目安に切り、読点は 2 つまで。長い修飾語を先に、短い修飾語を後に。
3. **文末に だ・である・です・ます を使わない**。
   - 名詞述語 → 体言止め：「実装は完了。」
   - 動詞述語 → 終止形のまま：「自動で再適用される。」「機械的に追従する。」
   - 連用中止・「〜ため」「〜とし」で文をつなぎ、ぶつ切りを避ける。文中の「である」は可。
4. **普通の日本語で言える語を英語・カタカナで書かない**。
   例：deterministic → 毎回同じ動き／setup → 準備／update → 更新／issue → 問題。
   原語のまま残すのは固有名詞と訳せない技術用語のみ（git・コマンド名・ファイルパス・skill 名）。
5. **数字を丸めない**。「32 件」を「約 30」「30+」「30 件ほど」と書かない。実数のみ。
6. **和文と英数字の境界に半角スペース**：「Claude を使って RAG を構築」。読点・句点の前後には入れない。
7. **表記を 1 文書で固定**：サーバ/サーバー等のゆれ・訳語と原語の混在を作らない。「済み」は漢字。
8. **見出しラベルの後は「：」**：「結論：〜」。砕けた見出しは端正な名詞句にする。

書き終わったら機械的に確認する：各段落の 1 文目だけで筋が通るか／文末に だ・である・です・ます が
残っていないか／丸めた数字・不要なカタカナ英語が残っていないか。
