# Specs Templates — Specification Template Collection

Templates for the specification documents generated by the `spec` skill. Covers 6 industry standards, selected by project scale and purpose.

## Template list

| File | Use | In one line | Recommended Tier |
|---|---|---|---|
| `spec-kit/spec.md.tpl` | Spec Kit spec | What to have the AI build (user stories + acceptance criteria) | 1-4 |
| `spec-kit/plan.md.tpl` | Spec Kit plan | The blueprint for how to build it | 1-4 |
| `spec-kit/tasks.md.tpl` | Spec Kit tasks | TDD-structured task breakdown | 1-4 |
| `prd.md.tpl` | Product Requirements Document | The contract for what to build (business-side view) | 2-4 |
| `design-doc.md.tpl` | Google-style Design Doc | The blueprint for how to build it (detailed engineering version) | 2-4 |
| `rfc.md.tpl` | HashiCorp-style RFC | A proposal soliciting agreement on how to change things | 3-4 |
| `adr.md.tpl` | Architecture Decision Record | A record of why it was decided that way (short form) | 1-4 |
| `scope.md.tpl` | Scope Doc | Agreement on the project's boundary lines | 3-4 |

## Principles for choosing

### Split by "what you have / what you don't"

- **What to build**: PRD / Spec Kit spec
- **How to build**: Design Doc / Spec Kit plan
- **Proposing a change**: RFC
- **Task breakdown**: Spec Kit tasks
- **Decision record**: ADR (written after the decision)
- **Boundary definition**: Scope Doc

### The core of AI-facing specs

Specs handed to AI agents (Claude Code / Cursor / Gemini CLI) must **state boundaries at 3 levels**:

- ✅ **Always**: always do this
- ⚠️ **Ask first**: ask the user before judging
- 🚫 **Never**: absolutely never

Without this, the AI fills gaps by inference (per the `spec-fidelity.md` rule).

## Recommended setup by Tier

| Tier | Scale | Required |
|---|---|---|
| **Tier 1** | Personal / prototype | `spec-kit/*` + `decisions/` (ADR format) |
| **Tier 2** | Small team | + `prd.md` |
| **Tier 3** | Mid-size company | + `design-doc.md` + `rfc.md` + `scope.md`, **AGENTS.md** |
| **Tier 4** | Enterprise | + `security/threat-model.md`, `runbooks/`, `compliance/` |

When the user runs `/spec`, they are asked interactively "which format this time?".

## File naming convention

Generated files go to `docs/specs/{YYYY-MM-DD}_{topic}_{type}.md`:
- `docs/specs/2026-04-20_auth-redesign_spec.md`
- `docs/specs/2026-04-20_auth-redesign_plan.md`
- `docs/specs/2026-04-20_auth-redesign_tasks.md`
- `decisions/ADR-0042_auth-redesign_{user}.md` (ADRs use sequential numbers + the existing decisions/ pattern)
