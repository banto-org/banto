# templates/ — Templates and Rules

Templates Banto deploys via `scripts/harness-setup.sh` — the rule files placed under `.claude/rules/` (and `~/.claude/rules/`), plus a CLAUDE.md skeleton (the project CLAUDE.md itself is generated by native `/init`).

## File list

### CLAUDE.md.template

Skeleton CLAUDE.md for project-specific information. Provides fields for language, framework, package manager, tests, directory layout, etc. Quality rules are split out into `.claude/rules/` by design.

### rules/

Templates for the rule files placed under `.claude/rules/`.

#### quality.md (code quality rules)

Rules on code quality. Always applied to all files. Covers banning unrequested feature additions, avoiding premature abstraction, preventing excessive error handling, etc.

#### safety.md (change safety rules)

Rules on the safety of changes. Always applied to all files. Covers confirmation before destructive operations, banning secret commits, banning direct lockfile edits, etc.

#### testing.md (testing rules)

Path-scoped rules applied only to test files. Active for files matching paths like `**/*.test.*`, `**/*.spec.*`, `**/tests/**`. Covers clear test naming, minimal mocking, one assertion per test, etc.

#### api.md (API rules)

Path-scoped rules applied only to API files. Active for files matching paths like `src/api/**`, `src/routes/**`, `app/api/**`. Covers input validation, structured error responses, security measures, etc.

## Rule scopes

| Rule | Scope | Condition |
|--------|---------|------|
| quality.md | All files | Always |
| safety.md | All files | Always |
| testing.md | Test files only | Path match |
| api.md | API files only | Path match |
