Evidence実測レポート

What the measurements say about ai-context. 実測からわかる ai-context の正しさ。

Does giving AI a project's memory — the ai-context store — actually work? We measured it directly: 5 benchmarks, 42 cells in total (46 independent runs of model × condition). Every number on this page is a measured value, not a rounded estimate.

「AI にプロジェクトの記憶（ai-context store）を持たせることは本当に効くのか」を実測した。5 つのベンチマーク・ 42 セル・延べ 46 走行（モデル × 条件の独立試行）による。このページの数値はすべて実測値であり、丸めた 概算ではない。

The scenario every developer lives daily: work is interrupted mid-feature, three design decisions already made, and a new session gets just two words — "continue this". Without the store, the AI honored 2 of 8 settled decisions and confidently re-implemented an already-rejected design. With the store: 8 of 8, zero re-asking. Same models — the only difference is memory.

Executive summary要旨

Five conclusions follow from the 42 cells.42 セルの実測から、結論は 5 つ導かれる。

1"Continue this" actually works「続きを進めて」が通じる

Interrupted mid-feature, a new session honored 8/8 settled design decisions with the store — 2/8 without it, including re-implementing a rejected design.実装途中で中断しても、store があれば新セッションは確定済みの設計判断を 8/8 守る。無ければ 2/8 — 棄却済みの設計の再実装まで起きる。

2The store is the only sourcestore が唯一の供給源

The store is the only source of project-specific knowledge: the correct-answer rate without it, 1.9/8, becomes 7.9/8 with it.プロジェクト固有知識は store が唯一の供給源であり、store なしの正答 1.9/8 が store ありで 7.9/8 になる。

Partial-credit scoring, reference value only — binary re-scoring not yet run.部分点採点・参考値（二値再採点は未実施）。

3Coding skill has saturatedコード力は飽和

In development tasks, coding skill is already saturated; the difference shows up in the judgment of "what not to expose." Only the group given the store's structural canonical reference achieved zero exposure of confidential-grade data.開発タスクではコード力はすでに飽和しており、差が出るのは「何を公開しないか」という安全境界の判断。store の構造正本を渡した群だけが機密相当データの露出をゼロにした。

4The store is cheaper to re-reference再参照は store が安い

Re-referencing an already-researched topic is about 33% cheaper via the store than web search, with fewer turns. Web wins only on freshness.研究済みトピックの再参照は、web 検索より store 参照が約 33% 安く、ターン数も少ない。鮮度だけは web が勝つ。

5Weak models get armed, not self-verification弱モデルは武装できるが自己検証は別

A weak model is lifted by index / router guidance (0 → 7.5/8), but the lack of self-verification cannot be substituted by tooling.弱いモデルは索引・ルーター案内で底上げされるが（0→7.5/8）、自己検証の欠如は道具では代替できない。

Five terms, one line each先に用語を 5 つだけ

Everything below uses these five words. Nothing else is jargon.以下の表と本文で使う言葉はこの 5 つだけ。これ以外に専門用語は出ない。

run走行

One independent attempt: a model solves the task once, in isolation.モデルに 1 回、独立に課題を解かせること。これを 1 走行と数える。

cellセル

One model × condition combination — e.g. "haiku without the store".「モデル × 条件」の組み合わせ 1 つ。例：「haiku × ハーネスなし」で 1 セル。

bareハーネスなし

The control condition: no store, no index — the model's own knowledge and plain file exploration only.比較の基準になる条件：store も索引も見せない。モデル自身の知識と、ファイルを直接探索する力だけで答えさせる。

harnessハーネス

The Banto condition: store + router guidance + ledger + full-text search, all available.Banto 一式を使える条件：store + 案内 + 台帳 + 全文検索。

ledger台帳

A machine-readable list of every document — for counting, auditing and completeness, not for reading.全ドキュメントの機械可読な一覧。数える・監査する・漏れなく列挙するための索引。

Method (common to every round)方法（共通）

  1. Subjects.対象モデル： Claude 4 models (sonnet / haiku / opus / fable). Each cell is run by an independent, mutually isolated fresh agent.Claude 4 モデル（sonnet / haiku / opus / fable）。セルごとに独立・相互隔離の fresh エージェント。
  2. Conditions.条件： "bare" = store / index access forbidden (the model's prior knowledge + plain file exploration only) / "harness" = banto's layer-0 router guidance + the ledger (jq queries against ontology.json) + full-text search + store access.「ハーネスなし」= store・索引の参照禁止（モデルの事前知識と、ファイルを直接探索する力のみ）。「ハーネス」= banto の層 0 ルーター案内 + 台帳（ontology.json への jq クエリ）+ 全文検索 + store 参照。
  3. Question / scoring separation.出題と採点の分離： Questions and answer keys (a 3–5-point checklist per question) were authored by an independent instance that closely read the primary documents. Development-task scoring used a fresh scoring agent doing mechanical inspection (re-execution, real-value cross-check, link resolution).問題と正解キー（要点チェックリスト 3〜5 項目/問）は独立インスタンスが一次文書を精読して作成。開発タスクの採点は fresh な採点エージェントが機械検査（再実行・実数照合・リンク解決）。
  4. Tokens.トークン： Measured values, summed from assistant usage in each cell's transcript.各セルの transcript から assistant usage を合算した実測値。
  5. Disclosed constraints.制約の開示： Descriptive statistics from 1 run per cell (haiku only, partially, at 3 runs) — no variance or confidence intervals. Known weaknesses regarding condition uniformity and scoring independence are listed under "Limitations" at the end.各セル 1 走行（haiku の一部のみ 3 走行）の記述統計であり、分散・信頼区間はない。条件の完全均一性・採点独立性に関する既知の弱点は本文末尾「Limitations」に列挙。

Interrupt → resume: does "continue this" work?中断 → 再開 —「続きを進めて」は通じるか

2 conditions × 2 models, one two-word instruction, scoring fixed before the runs2 条件 × 2 モデル・指示は一言だけ・採点基準は走行前に固定

Takeaway: settled design decisions survive a session boundary only if they are stored — 2/8 without the store, 8/8 with it, on the same models.結論：確定済みの設計判断は、store がなければセッション境界を 2/8 しか越えられない。store があれば 8/8 — 同じモデルで。

Setup: a notification API mid-implementation (2 of 5 tasks done). The previous session settled three decisions — sliding-window log (fixed window rejected for boundary bursts), Redis sorted set (in-memory rejected: replicas don't share it), and a frozen 429 response shape that client SDKs depend on — plus a 30 req/min limit. A fresh session gets the repo and exactly one instruction: "continue this". The bare condition sees only the repo; the harness condition also gets the store (decisions, task ledger, checkpoint). Code was inspected mechanically after each run.

  • Finding: at this scale (roughly 400 documents), strong-model accuracy doesn't depend on the condition. Haiku's errors trace to one root cause — "lack of self-verification": a trap where square brackets in a filename get misread by glob as a character class and return 0 hits caught haiku in 3 of 6 runs, and it accepted the 0 without verifying.
  • 発見: 強モデルの精度はこの規模（400 文書級）では条件に依存しない。haiku の誤りの正体は「自己検証の欠如」。ファイル名の角括弧が glob に文字クラスとして誤解釈され、0 件になる罠に 6 走行中 3 回落ちた。しかもその 0 件を無検証で受理した。
  • Sonnet hit the same trap but caught it on its own and recounted. Whether that self-correction is present is the threshold for whether implementation can be entrusted to a model.
  • sonnet は同じ罠を踏んだ後、自力で気づき数え直した。この self-correction の有無が実装を任せられるかの最低ライン。

Overall conclusion総合結論

  1. The existence-value of the ai-context store was directly measured.ai-context store の存在価値は直接測定できた。 Proprietary-knowledge accuracy went 0 → over 80%; a weak model gets armed; the ledger is auditable. 固有知識 0 → 8 割超・弱モデルの武装・監査可能な台帳。
  2. The harness's essential value is "boundary," not "accuracy."ハーネスの本質価値は「精度」より「境界」。 Now that coding skill has saturated, the value has shifted to correct structural understanding and the judgment of "what is okay to publish." コード力が飽和した現在、価値は正しい構造理解と「公開してよいものの判断」に移っている。
  3. Cost.コスト Re-referencing already-researched knowledge is about 33% cheaper via the store than the web. On the knowledge benchmark, 3–6x the input buys more than 4x the correct-answer rate. 研究済み知識の再参照は store が web 比 約 33% 安。知識ベンチでは入力 3〜6 倍で正答 4 倍超を買う。
  4. Model operations.モデル運用 sonnet is sufficient for implementation (on the precondition that it's given the structural canonical reference). Auditing should use a different model. Haiku should be limited to mechanical search — the lack of self-verification cannot be fixed by tooling. 実装は sonnet で足りる（ただし構造の正本を渡すことが前提条件）。監査は別モデル。haiku は機械的検索限定——自己検証の欠如は道具では治らない。

Limitations

Disclosed for the sake of honesty誠実性のための開示

  • Descriptive statistics from 1 run per cell (haiku only, partially, at 3 runs). No variance, no confidence intervals.
  • 各セル 1 走行（haiku の一部のみ 3 走行）の記述統計。分散・信頼区間なし。
  • Knowledge-benchmark scoring checks against an explicit key, but some scorers were not independent instances.
  • 知識ベンチの採点は明示キーとの突き合わせだが、採点者の一部は独立インスタンスでない。
  • A few cells had tooling-environment differences, substituted with an equivalent method (disclosed per cell). Only harness×haiku had one extra sentence of guidance text.
  • 一部セルでツール環境差があり等価手段で代替（各セル開示済み）。ハーネス×haiku のみ案内文が 1 文多い。
  • The answer keys themselves were AI-authored (cross-validated by independent answers from multiple models converging on the same facts).
  • 正解キー自体も AI 作成（複数モデルの独立回答が同一事実へ収束することで相互裏付け）。
  • Cost normalization depends on an assumed pricing ratio (convert to your own price sheet for absolute amounts).
  • コスト正規化は料金比率の仮定に依存（絶対額は各自の料金表で換算のこと）。
