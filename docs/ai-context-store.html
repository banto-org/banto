AI-Context-StoreAI コンテキストストア

Knowledge that survives the session. セッションを越えて残る知識。

Every decision, research note, working state, and checkpoint lives in a central store outside your repo. Banto injects it at the start of every session and saves it at the end — so a /clear or a compaction never costs you the thread. Your code stays clean; the knowledge accrues.

決定・調査・作業状態・チェックポイントは、すべて repo の外の中央ストアに置く。 Banto がセッション開始時に注入し、終了時に保存する — /clear や自動圧縮で文脈を失わない。 コードは綺麗なまま、知識だけが積もる。

Each session saves; the next session reads it back.各セッションが保存し、次のセッションが読み込む。

Everything built up in a conversation — decisions, research, half-finished plans — vanishes on /clear or auto-compaction. Next session, you explain it all again.会話で積み上げた決定・調査・途中の計画は、/clear や自動圧縮で消える。次のセッションで、同じ説明をまた繰り返す。

01

What it isこれは何か

An external memory, one per project. It accumulates decisions, research, and working state — and recalls them automatically at session start.プロジェクトごとの外部メモリ。決定・調査・作業状態を貯め、セッション開始時に自動で思い出す。

  • Context survives /clear — the thread continues
  • /clear しても文脈が残る
  • Your code repo stays clean — knowledge lives in the store
  • コードリポジトリは汚れない — 知識はストアへ
  • Everything accumulated is searchable later
  • 貯めた内容を後から検索できる

How Banto uses the storeBanto はストアをこう使う

The store is not just a place to put files. The ai-context skill records, navigates, and maintains it — no command to memorize; ask in plain words and the right one is reached.ストアはただの置き場ではない。ai-context skill が記録・案内・保守する — コマンドを覚えなくても、普通の言葉で頼めば届く。

captureRecord記録

  • memo · capture a note into the storeメモをストアへ
  • knowledge · promote a draft to durable knowledge下書きを恒久ナレッジへ昇格
  • decisions are auto-numbered and saved決定は自動採番して保存

navigateDrive前進

  • next · advance to the next open task次の未完タスクへ
  • phase-done · close a phase, auto-archivePhase 完了・自動アーカイブ
  • sort · route a stray doc to its home散らかった doc を振り分け

maintainKeep healthy健全に保つ

  • doctor · lint broken links / orphans / stale decisions (detect only)壊れたリンク・孤立ファイル・古い決定を診断（検出のみ）
  • bootstrap · back the store with a GitHub repoGitHub の置き場をストアに登録
  • local · pin a project local-onlyプロジェクトをローカル固定
04

It runs by itself自動で回る

Banto hooks into Claude Code's lifecycle, so the store is injected, guarded, and saved automatically — the human never calls it. Three scenes.Banto が Claude Code のライフサイクルに hook を張るため、ストアは自動で注入・防御・保存される — 人間は呼ばない。場面は 3 つ。

1
at session start開始時

Remember思い出す

The moment a session starts, the store path, the latest checkpoint, today's decisions, and the current working state are injected. When drafts exceed 10, a promote-or-delete review is offered.セッション開始と同時に、ストアの場所・直近チェックポイント・本日の決定・現在の作業状態を注入。下書きが 10 件を超えると、昇格 / 削除のレビューを提示。

2
while working作業中

Guard & record守る・記録する

Before a tool runs, deterministic safety valves fire: a write that would leak an internal name or PII into a client file is stopped (egress-guard); a dangerous shell command is stopped (safety-guard); a direct push to main is stopped (odd-kill-switch). Every saved decision or doc regenerates the search text automatically.tool 実行の前に、決定論の安全弁が働く：内部名や個人情報が客先ファイルへ出そうなら止める（egress-guard）。危険なシェルコマンドを止める（safety-guard）。main への直接 push を止める（odd-kill-switch）。決定や doc を書き込むたびに、検索用テキストを自動で再生成。

3
at end / compaction終了・圧縮時

Save保存する

Before context is squeezed, a checkpoint is saved to sessions/ and the store is synced. A "done" claim with red verification is blocked (verify-claim-guard), and a lesson draft is kept for later.圧縮の前にチェックポイントを sessions/ へ保存し、ストアを同期。検証が通らないままの「完了」は遮断（verify-claim-guard）。教訓の下書きを残す。

Appendix: the six hooks, by lifecycle event付録：ライフサイクル別の 6 つの hook
SessionStart
Injects the absolute store path, the latest checkpoint, today's decisions, and the active workspace. When drafts exceed 10, a promote-or-delete review is offered.ストアの絶対パス・直近チェックポイント・本日の決定・現在のワークスペースを注入。下書きが 10 件を超えると昇格 / 削除レビューを提示。
UserPromptSubmit
Reminds where decisions are saved, and recommends a checkpoint as a phase wraps up.決定の保存先を提示し、Phase の区切りでチェックポイントを推奨。
PreToolUse
Guards before the action runs: egress-guard stops internal names / PII heading into a client file; safety-guard stops dangerous shell commands; odd-kill-switch stops a direct push to main.実行前の防御。内部名や個人情報の客先ファイル流出を止める（egress-guard）。危険なシェルコマンドを止める（safety-guard）。main への直接 push を止める（odd-kill-switch）。
PostToolUse
A write into decisions/ or docs/ regenerates the combined search text (milliseconds, no model) — internal search always sees the latest.decisions/・docs/ への書き込みで、検索用の連結テキストを再生成（ミリ秒・モデル不要）。内部検索が常に最新を見る。
PreCompact
Writes a checkpoint to sessions/ and syncs the store before context is squeezed.圧縮の前にチェックポイントを sessions/ へ書き、ストアを同期。
Stop
verify-claim-guard blocks a "done" claim while verification is red; a self-improvement loop keeps a lesson draft in learnings/.検証が通らないままの「完了」を遮断（verify-claim-guard）。自己改善ループが教訓の下書きを learnings/ に残す。

Enforcement is hooks, never promises — the same principle across the whole harness.強制は約束ではなく hook — ハーネス全体を貫く原則。

05

Never blocks — migrate later止めない。移行は後から

Setup never gates the work. Before any registration, a temporary local home is used — move it to GitHub whenever you like.準備で作業を止めない。登録前でも仮の置き場ですぐ動き、後から GitHub の置き場へ移せる。

1Works immediatelyすぐ動く

An unregistered project is first saved to a temporary local home (~/ai-context-local/<project>/, same layout). Nothing waits on setup.未登録のプロジェクトは、まず仮のローカル置き場（~/ai-context-local/<project>/・同じ構成）に保存される。準備を待たずに動く。

2Migrate later後から移せる

bootstrap registers or creates a private GitHub store, then pulls the local content in.bootstrap が非公開の GitHub ストアを登録 / 作成し、ローカル分を取り込む。

3Additive only追加のみ

Migration only adds — nothing already in the store is overwritten.移行は追加のみで、既存の内容を上書きしない。
