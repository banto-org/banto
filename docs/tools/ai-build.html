ai-build — AI feature flow · evalai-build — AI 構築フロー · eval

ai-build is dev-loop's AI-specialized sibling: the same skeleton — implement, verify, fix, iterate — but the verify stage becomes LLM-as-judge eval, and the design stage gains method selection (prompt / RAG / fine-tune) and model selection. An AI feature isn't done at "it ran"; quality has to be measured.

ai-build は dev-loop の AI 特化版。実装 → 検証 → 修正 → 反復という骨格は同じで、検証段が LLM-as-judge の eval に、設計段に手法選定（prompt / RAG / fine-tune）とモデル選定が加わる。AI 機能は「動いた」で終わらず、品質は測って初めて分かる。

01

What it does何をするか

Wires together, doesn't reimplementつなぐだけ。再実装しない

Internal search is delegated to search, freshness-critical lookups to research, and Claude's ids / pricing / params to claude-api. ai-build's own job is framing success criteria, choosing a method + model, and running the eval loop.

内部検索は search、鮮度が効く調査は research、Claude の id・価格・パラメータは claude-api skill へ委譲する。ai-build 自身の仕事は、成功基準の明確化と手法 + モデル選定、eval ループの実行に絞る。

LLM-as-judge evalLLM-as-judge の eval

A minimal ai-eval-judge.sh scores a JSONL case set 0–100 via claude -p (fail-open if claude/jq are absent). Green/red against a threshold reuses dev-loop's verify-claim skeleton — no false "done" while eval is red.

最小実装の ai-eval-judge.sh が JSONL のケース集を claude -p で 0–100 点採点する（claude/jq 不在は fail-open）。閾値での green/red は dev-loop の verify-claim 骨格を流用し、eval が red のまま「完了」を主張できない。

How it works仕組み

Frame (success criteria)Frame（成功基準） → searchsearch → researchresearch → Design (method + model, confirm)Design（手法 + モデル、確認） → Implement実装 → EVAL → iterateEVAL → 反復
