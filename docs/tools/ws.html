Workspace & metaワークスペース & メタ

ws — Workspace + git-town orchestrator for the 3-tier branch modelws — ワークスペースと git-town を束ねる 3 階層ブランチオーケストレータ

ws manages topic-based workspaces and drives a 3-tier branch model — main, epic, and task worktrees — through git-town. It detects intent straight from natural language, so starting a large scope, splitting off parallel work, finishing a task, or shipping to main never requires memorizing a command.

ws はトピック単位のワークスペースを管理し、main・epic・task worktree の 3 階層ブランチ運用を git-town で駆動する。自然文からインテントを直接検出するため、大枠スコープの開始・並列作業の切り出し・完了・main への反映まで、コマンドを覚える必要はない。帳簿系の操作（sync・cleanup）は自動実行、構造を作る操作（epic 新設）は採用解釈つきで提案し、PR や main のような不可逆な操作だけ確認を挟む。

1

What it does何をするか

3-tier branch operation3 階層ブランチ運用

Four operations map onto git-town: epic (git town hack + workspace creation), task (git town append + a physically separate worktree), done (test → git town merge → sync → worktree cleanup), and ship (git town propose, a PR). Drift from an epic propagates to every child task via git town sync.

4 つの操作を git-town にマッピングする。epic（git town hack + ワークスペース作成）、task（git town append + 物理分離した worktree）、done（テスト → git town merge → sync → worktree 削除）、ship（git town propose による PR 作成）の 4 つ。epic の更新は git town sync で全 task へ連鎖する。

Self-initiated parallel proposals並列の自発提案

Even without the user saying "in parallel", ws judges whether work splits into independent subtasks (no shared files, no sequential dependency) and proposes parallelizing them — choosing between a short-lived fan-out Agent and a longer-running task worktree.

ユーザーが「並行で」と言わなくても、独立した複数サブタスク（同一ファイル非接触・直列依存なし）に分割できると判断すれば、並列化を自発的に提案する。判断基準は、短命な fan-out Agent か、並走ブランチとなる task worktree かの二択。

How it works仕組み

intent detectionインテント検出 → epic (hack + WS)epic（hack + WS） → task (append + worktree)task（append + worktree） → done (merge + sync)done（merge + sync） → ship (PR, human gate)ship（PR・人間ゲート）
番 Judgment is split by risk: bookkeeping (sync, cleanup, done detection) runs silently; structure-creating moves (a new epic) come with a disclosed adopted interpretation; only irreversible, outward-facing moves — a PR, a merge into main — pass through a human confirmation, exactly once. 判断はリスクで分担する。帳簿系（sync・cleanup・done 検出）は黙って自動実行し、構造を作る操作（epic 新設）は採用解釈を開示して提案し、PR や main への反映のような不可逆で外向きの操作だけ、1 度だけ人間の確認を挟む。
