architect — the read-only design advisorarchitect — コードを変えない設計顧問

architect investigates the existing code, weighs the trade-offs, and returns a structured proposal inside the conversation. It never edits a file and never writes an artifact — the proposal itself is the deliverable. It runs on the opus model.

architect は既存コードを調査し、トレードオフを整理して、会話の中で構造化した提案を返す。ファイルは一切変更せず、成果物ファイルも作らない。提案そのものが成果物であり、opus モデルで動く。

02

What it does何をするか

The analysis runs through a fixed framework: a reversibility lens (high — refactoring, renaming / medium — DB schema or API changes / low — data deletion, retiring a public API), a minimal-change principle, and a design quality check (single responsibility, circular dependencies, abstraction level, testability).

分析は固定のフレームワークに沿う。可逆性の観点（高＝リファクタリング・リネーム／中＝DB スキーマや API 変更／低＝データ削除・公開 API の廃止）、最小変更の原則、設計品質チェック（単一責任・循環依存・抽象化レベル・テスタビリティ）で構成する。

The proposal always comes back in the same six-heading format: Current state, Issues, Proposal, Trade-offs, Risks, Next actions. Before analyzing, it greps the ai-context base's {base}/decisions/ for conflicting prior decisions and folds any conflict into "Current state" and "Risks".

提案は常に同じ 6 見出し（現状・課題・提案・トレードオフ・リスク・次のアクション）で返る。分析に入る前に ai-context ベースの {base}/decisions/ を Grep し、現テーマと矛盾する既存決定があれば「現状」と「リスク」に必ず反映する。

03

When it firesいつ動くか

review the designarchitecture decisiontechnology selectiondependency designdesign discussion changing the implementationgenerating a spec document"design it and just implement"simple naming / placement

Changing the implementation routes to debugger or self-driving implementation; generating a specification document routes to the spec skill; simple naming or placement proceeds with an adopted interpretation instead of a design review.

実装を変更する用件は debugger か自走実装へ、仕様書を生成する用件は spec skill へ回る。単純な命名・配置は設計レビューを挟まず、採用した解釈でそのまま進む。

04

Invocation呼ばれ方

architect is launched from the main session with the Agent tool — it is not called directly by the user, and it never fires on its own.

architect は本体セッションから Agent ツールで起動する。ユーザーが直接呼ぶものではなく、単独で動き出すこともない。

// example invocation from the main session
Agent({
  subagent_type: "architect",
  description: "Review the session store split",
  prompt: "ai-context base: {base}. Review whether splitting sessions/ by workspace is sound. Check {base}/decisions/ for conflicting prior calls first."
})
05

How it works仕組み

0. Grep decisions/
→
1. investigate code
→
2. weigh trade-offs
→
3. return structured proposal
→
4. record patterns to memory
番

If no ai-context base was passed in the prompt, architect skips the decisions check and states in its result that the check was not performed — it never guesses at a base path.

プロンプトに ai-context ベースが渡されていない場合、architect は decisions チェックを省略し、実施しなかった旨を結果に明記する。ベースパスを推測することはない。
