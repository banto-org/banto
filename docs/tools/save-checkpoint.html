save-checkpoint — session snapshotsave-checkpoint — セッション保存

Snapshots the current session — what's being worked on, how it got there, confirmed decisions, open issues, and next steps — under {base}/sessions/, then recommends exactly one of compact or clear. It never runs either command itself; the user always decides.

現在のセッション — 何に取り組んでいるか、経緯、確定した決定、未解決の論点、次の手順 — を {base}/sessions/ 配下へ保存し、compact か clear のどちらか一方だけを推奨する。/compact・/clear 自体は決して自分で実行せず、判断は常にユーザーに委ねる。

01

What it does何をするか

Collects diagnostics before writing: total decision logs, today's decisions, existing checkpoints, research count, and spec files — then writes {base}/sessions/checkpoint-{YYYY-MM-DD}-{HHMM}.md with what's being worked on, how it got there, decisions, open issues, changed files, and next steps.

診断情報を先に収集する：決定ログ総数、今日の決定数、既存チェックポイント数、リサーチ数、spec ファイルを確認したうえで、{base}/sessions/checkpoint-{YYYY-MM-DD}-{HHMM}.md に、現在の作業内容・経緯・決定・未解決論点・変更ファイル・次の手順を書く。

Never presents both options. If decision logs and the checkpoint are both saved with nothing left unwritten, it recommends clear (reclaim the full context window). Otherwise it recommends compact with a concrete reason.

両論併記は絶対にしない。決定ログとチェックポイントが保存済みで未保存の重要情報がなければ clear（コンテキストを丸ごと取り戻せる）を推奨し、そうでなければ具体的な理由とともに compact を推奨する。

02

When it firesいつ動くか

"save a checkpoint"「チェックポイント保存」 "save the state"「状態保存して」 "save before clear"「clear前に保存」 "save before compact"「compact前に保存」 a bare mention of compact/clear, no save request保存を求めない単なる compact/clear への言及 recording a design decision → ai-context設計判断の記録 → ai-context
03

How to use使い方

$ /save-checkpoint # collects diagnostics, writes the checkpoint, recommends compact or clear

"save the state before I clear" fires the same procedure as the explicit command.

「clear する前に状態を保存して」のような自然文でも、明示コマンドと同じ手順が動く。
