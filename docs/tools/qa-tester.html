qa-tester — one target, the right tool auto-pickedqa-tester — 対象を見て道具を自動で選ぶ

qa-tester auto-detects whether the target is web, desktop, or mobile, then runs E2E, UI, and behavior-verification tests with the best-fit tool — Claude in Chrome, Playwright, Computer Use, or agent-device. It runs on the sonnet model and never saves documents itself.

qa-tester は対象が web / desktop / mobile のどれかを自動判定し、Claude in Chrome・Playwright・Computer Use・agent-device のうち最適なツールで E2E・UI・動作検証テストを実行する。sonnet モデルで動き、ドキュメントの保存は自分では行わない。

02

What it does何をするか

For web, Claude in Chrome is preferred (context → new tab → navigate → read page → interact → check console); Playwright MCP is the fallback when the Chrome extension isn't connected. Responsive checks run at 375x667, 768x1024, and 1280x800. Native apps go through Computer Use; mobile apps go through the agent-device skill, skipped and reported if not installed.

web では Claude in Chrome を優先（タブ一覧取得 → 新規タブ作成 → 遷移 → ページ確認 → 操作 → コンソール確認）。Chrome 拡張が未接続なら Playwright MCP へフォールバック。レスポンシブは 375x667・768x1024・1280x800 で確認する。ネイティブアプリは Computer Use、モバイルアプリは agent-device skill を使い、未インストールならスキップしてその旨を報告する。

Three test perspectives: functional (main-flow behavior, edge cases, error behavior), UI (rendering, layout breakage, animations), and error detection (console errors, crashes, network anomalies). Every result comes back in a fixed structure — execution environment, pass/fail summary, per-case detail, failure detail, recommended fixes — with screenshots as evidence.

観点は 3 つ。機能テスト（メインフロー・エッジケース・エラー時の動作）、UI テスト（レンダリング・レイアウト崩れ・アニメーション）、エラー検出（コンソールエラー・クラッシュ・ネットワーク異常）。結果は常に同じ構造（実行環境・合否サマリー・テスト詳細・失敗詳細・推奨修正）で返り、スクリーンショットをエビデンスとして添える。

Unit tests run directly with a test runner like pytest; API tests are covered by a single curl; a simple link check needs no agent at all.

ユニットテストは pytest などのテストランナーを直接実行、API テストは curl 一発で十分、単純なリンクチェックはエージェントを介さない。

04

Invocation呼ばれ方

qa-tester is launched from the main session with the Agent tool. It never saves documents itself — a subagent doesn't receive the SessionStart injection and so doesn't know the store-first base — so the caller saves the returned result under {base}/docs/ with a [QA] prefix.

qa-tester は本体セッションから Agent ツールで起動する。ドキュメントの保存は自分では行わない（サブエージェントは SessionStart の注入を受け取らず store-first のベースを知らないため）。返された結果は、呼び出し元が {base}/docs/ に [QA] プレフィックスで保存する。

// example invocation from the main session
Agent({
  subagent_type: "qa-tester",
  description: "E2E test the checkout flow",
  prompt: "Target: https://staging.example.com/checkout (web). Verify the full purchase flow and check for console errors at 375x667 and 1280x800."
})
