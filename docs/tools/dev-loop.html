dev-loop — self-driving builddev-loop — 自走ビルド

dev-loop takes a big task — a spec, a document, a large backlog item — and decomposes it into small tasks, then implements, verifies, fixes, and re-verifies each one until tasks.md is exhausted. Only exceptions come back to the owner: the bantō contract, applied to the build itself.

dev-loop は、spec やドキュメント、大きめのタスクといった大玉を小型タスクへ分解し、実装 → 検証 → 修正 → 再検証を tasks.md が尽きるまで回す skill。上がってくるのは例外だけ — 番頭の契約を、ビルドそのものに適用したもの。

01

What it does何をするか

Decompose, then loop分解して周回

Independent small tasks (no shared file, no sequential dependency) get flagged for parallel fan-out. The decomposition plan is confirmed with the owner once, up front — the one human gate before the loop runs unattended.

同一ファイルに触れず直列依存も無い独立タスクは、並列 fan-out の候補としてフラグを立てる。分解プランは最初に一度だけ owner へ提示し確認する — 以後を無人で回す前の唯一の人間ゲート。

Reuses every existing part既存部品の再利用

No new scripts get created. Verification aggregates build → test → API through the existing verify-run.sh; a red result routes to the debugger agent for root-cause fixes; a green result gets audited by a fresh opus-model agent before commit.

新規スクリプトは作らない。検証は既存の verify-run.sh が build → test → API を集約し、red なら debugger agent が root cause を修正、green なら opus モデルの別コンテキスト監査エージェントが spec 適合を確認してから commit する。
