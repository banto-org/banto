spec — interactive design docsspec — 対話で設計書

spec generates an industry-standard specification through dialogue before a single line of code is written. It picks from 6 templates — Spec Kit, PRD, Design Doc, RFC, ADR, Scope Doc — and stops the moment design is done, unless told to keep going into implementation.

spec は、コードを書く前に業界標準の仕様書を対話で生成する skill。Spec Kit・PRD・Design Doc・RFC・ADR・Scope Doc の 6 種から選び、設計が終わった時点で止まる。実装まで進めるのは、続行の指示があったときだけ。

01

What it does何をするか

6 industry-standard formats業界標準 6 種

Spec Kit (3-file set, the AI-coding era standard) / PRD / Design Doc / RFC / ADR / Scope Doc. Formats can combine — "1 + 5" produces Spec Kit plus an ADR for the key technical decision.

Spec Kit（3 ファイルセット、AI コーディング時代の標準）/ PRD / Design Doc / RFC / ADR / Scope Doc。組み合わせも可能で、「1 + 5」なら Spec Kit と重要判断の ADR を両方生成する。

Explicit AI boundariesAI 境界の明示

Every generated spec carries a mandatory ✅ Always / ⚠️ Ask first / 🚫 Never section, so the AI never fills an ambiguity gap by guessing. Goal-fork ambiguity is confirmed in advance; everything else proceeds as an adopted interpretation, disclosed in the final report.

生成する spec には必須の ✅ Always / ⚠️ Ask first / 🚫 Never 節が入り、AI が推測で穴を埋めない。ゴール分岐級の曖昧さは事前確認、それ以外は採用解釈で進めて最終報告に開示する。
