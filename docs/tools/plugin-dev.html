plugin-dev — Scaffold and refactor Claude Code pluginsplugin-dev — Claude Code プラグインの生成と改修

plugin-dev builds new plugins, skills, and hooks against the official plugin reference, and refactors an existing skill without breaking its trigger words or invocation routes. New creation runs a requirements interview, decides whether a skill needs a companion rule + hook (the Layer 3 trio), checks whether it warrants the heavier HeavySkill template, then generates each file from a dedicated reference.

plugin-dev は、公式のプラグインリファレンスに沿って新規プラグイン・skill・hook を生成し、既存 skill はトリガー語や起動経路を壊さずに改修する。新規作成では要件をヒアリングし、rule + hook を併設する Layer 3 trio が要るかを判定し、重めの HeavySkill テンプレが要るかを確認したうえで、各ファイルを専用の参照資料から生成する。

1

What it does何をするか

New creation新規作成

Interviews for plugin name, purpose, required components, and distribution target; decides standalone (.claude/) vs plugin; checks Layer 3 trio and HeavySkill applicability; then generates plugin.json, SKILL.md, hooks.json, .mcp.json, and agents from matching reference templates.

プラグイン名・目的・必要なコンポーネント・配布先をヒアリングし、standalone（.claude/）かプラグインかを判定する。Layer 3 trio と HeavySkill 適用可否を確認したうえで、plugin.json・SKILL.md・hooks.json・.mcp.json・agent を対応する参照テンプレから生成する。

Refactor moderefactor モード

Reads the target SKILL.md and its usage evidence, compares it against the quality-scoring criteria, presents improvement proposals, applies them with Edit, then re-verifies via plugin-audit. Backward compatibility with existing trigger words is the top priority, unlike new creation.

対象の SKILL.md と利用状況を読み、品質スコアリング基準と突き合わせて改善提案を提示し、Edit で適用したのち plugin-audit で再検証する。新規作成と違い、既存のトリガー語との後方互換が最優先。

番 When in doubt on the trio, build the skill alone first and add a rule or hook later if operation demands it — plugin-dev avoids proposing structure the skill doesn't yet need. trio の要否に迷ったら、まず skill だけを作り、運用で必要が出てから rule や hook を足す。plugin-dev はまだ要らない構造を提案しない。
