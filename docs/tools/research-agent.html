research-agent — the worker behind researchresearch-agent — research の実働部隊

research-agent is not called directly by the user. The research skill is the orchestrator: it launches research-agent in parallel to investigate external sources — web, GitHub, arxiv, official docs — and save a structured Markdown report to docs/research/ under the ai-context base. It runs on the sonnet model.

research-agent はユーザーが直接呼ぶものではない。research skill がオーケストレーターであり、外部ソース（Web / GitHub / arxiv / 公式ドキュメント）の調査を research-agent に並列で投げ、ai-context ベース配下の docs/research/ へ構造化 Markdown として保存させる。sonnet モデルで動く。

02

What it does何をするか

It never uses WebFetch to read a URL's body — a small model would summarize it and the content couldn't be verified. Instead it calls webread.sh, which runs trafilatura locally (no LLM) to pull the full text as Markdown, then reads that full text itself. WebSearch is still used to locate URLs.

URL 本文を読むのに WebFetch は使わない（小さいモデルが要約してから返すため、内容を検証できない）。代わりに webread.sh を呼び、trafilatura（純粋にローカル・LLM なし）で本文全文を Markdown として取得し、その全文を自分で読む。URL を見つけるための WebSearch は従来どおり使う。

Engineering and academic sources are kept separate — mixing them lowers search precision. Engineering topics prioritize official docs, then GitHub Issues/Releases/PRs, Stack Overflow, technical blogs, and X/Twitter. Academic topics follow a field-specific venue list (arXiv → alphaXiv → OpenReview for AI/CS; bioRxiv → medRxiv → PubMed → Nature for life sciences), sorted by date with the current year in the query — never by version number.

エンジニア系と学術系のソースは分ける（混ぜると検索精度が落ちる）。エンジニア系は公式ドキュメントを最優先し、GitHub Issues/Releases/PR・Stack Overflow・技術ブログ・X/Twitter と続く。学術系は分野別の venue リスト（AI/CS は arXiv → alphaXiv → OpenReview、生命科学は bioRxiv → medRxiv → PubMed → Nature）に従い、日付順＋当年を含めた検索で最新を取る。バージョン番号での検索は禁止。

03

When it firesいつ動くか

launched in parallel from the research skillfan out research in parallel internal searchreferencing an existing document only

Internal search over the local ai-context base routes to the search skill; referencing an existing document needs only a direct Read.

ローカル ai-context ベースの内部検索は search skill へ回る。既存ドキュメントの参照だけなら直接 Read で足りる。

04

Invocation呼ばれ方

Only the research skill launches research-agent, via the Agent tool, and always in parallel across subtopics. It passes an absolute save-target path — the canonical route — plus the conversation language and any existing research/URLs/decisions to build on.

research-agent を起動するのは research skill のみで、Agent ツール経由・常にサブトピックごとの並列。プロンプトには保存先の絶対パス（正規ルート）と会話言語、活用すべき既存リサーチ・URL・decision を渡す。

// research skill fans this out per subtopic, in parallel
Agent({
  subagent_type: "research-agent",
  description: "Survey Claude Agent SDK subagent patterns",
  prompt: "会話言語: ja. Save to {base}/docs/research/. Existing research: {path}. Topic: subagent isolation modes in the Claude Agent SDK, current year."
})
05

How it works仕組み

1. read existing context
→
2. WebSearch for URLs
→
3. webread.sh full text
→
4. write Markdown
→
5. save to docs/research/
番

If the absolute base path can't be resolved, it does not write to a relative .ai-context/ path — it treats the save target as unknown, returns the full report in the result, and reports the failure.

ベースの絶対パスが解決できない場合、相対的な .ai-context/ へは書き込まない。保存先を不明として扱い、結果に全文を返し、その旨を報告する。
