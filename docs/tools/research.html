research — external research, saved to storeresearch — 外部調査 → ストア

Goes out to the Web, GitHub, arxiv, and X for information Banto doesn't already have, then documents it under {base}/docs/research/ instead of leaving it as a one-off chat answer. It always checks the local store with search first — store-first, web second.

Banto がまだ持っていない情報を Web・GitHub・arxiv・X から取りに行き、会話で終わらせず {base}/docs/research/ へドキュメント化する。常にまずローカル store を search で確認する — store-first、web はその後。

01

What it does何をするか

Medium-aware routing. Static docs go through webread (full-text, no summary); GitHub Issues/Releases go through research-agent; login-gated sites (X, Slack) go through Claude in Chrome with a confirmation gate first; academic topics are split from engineering sources by field.

媒体別ルーティング。静的ドキュメントは webread（要約なし全文）、GitHub Issues/Releases は research-agent、ログイン必須サイト（X、Slack）は事前確認つきで Claude in Chrome、学術トピックは分野別にエンジニア系ソースと分けて扱う。

Runs 5–10 research-agent subagents in parallel per subtopic. For claims where accuracy drives a business or safety decision, it routes to the heavier deep-research Workflow (adversarial 3-vote verification, ~4M tokens per run) instead of a single cross-check.

サブトピックごとに research-agent を 5〜10 並列起動。主張の正確さが業務・安全上の判断を左右する場合は、単純なクロスチェックではなく重い deep-research Workflow（敵対的 3 票検証、1 回あたり約 4M トークン）へルーティングする。

03

How to use使い方

$ /research Claude Agent SDK の最新のサブエージェント制御パターン # search first (store-first gate), then decompose into subtopics $ /research どちらの vector DB を使うべきか、pgvector vs Qdrant # parallel research-agent per subtopic, cross-checked, saved to docs/research/

A plain "what's the current state of streaming tool calls in the API" fires the same procedure.

「API のストリーミング tool call は今どうなってる」のような自然文でも同じ手順が動く。
