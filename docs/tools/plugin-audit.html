plugin-audit — 15-axis quality audit for plugins and skillsplugin-audit — プラグイン・スキルの 15 軸品質監査

plugin-audit checks a plugin, or a single skill passed as skills/<name>, against the official plugin reference (Phases 1-8.5) and then a 15-axis quality rubric (Phase 9): static axes computed by scripts, plus judgment axes handed to an independent subagent so a skill never grades its own homework. The audit itself is read-only — applying any fix always asks first.

plugin-audit は、プラグイン全体、または skills/<name> で渡した単一 skill を、公式のプラグインリファレンス（Phase 1-8.5）と 15 軸の品質ルーブリック（Phase 9）で監査する。静的軸はスクリプトが計算し、判定軸は独立したサブエージェントに委ねるため、skill が自分の答案を自分で採点することはない。監査自体は read-only で、修正の適用は必ず先に確認する。

1

What it does何をするか

Official compliance (Phases 1-8.5)公式準拠チェック（Phase 1-8.5）

Directory structure, plugin.json, SKILL.md frontmatter and body, hooks.json, .mcp.json, deprecated commands/*.md, unofficial components, and the limitations that apply to plugin agents (hooks, mcpServers, and permissionMode are ignored on them).

ディレクトリ構造・plugin.json・SKILL.md のフロントマターと本文・hooks.json・.mcp.json・非推奨の commands/*.md・非公式コンポーネント、そして plugin agent に適用される制限（hooks / mcpServers / permissionMode は無視される）を点検する。

15-axis quality audit (Phase 9)15 軸品質監査（Phase 9）

Covers YAML validity, body structure, routing-description format, measured routing precision, HeavySkill applicability, cross-skill disambiguation, generality, rule-externalization fitness, Layer 3 consistency, ODD application, usage, permission-scope minimality, containment, content hygiene, and cross-skill reference consistency — 15 axes in total.

YAML 妥当性・本文構造・description のルーティング形式・実測ルーティング精度・HeavySkill 適用妥当性・cross-skill 境界曖昧さ・汎用性・rule 外部化適性・Layer 3 整合性・ODD 適用・使用度・権限スコープ最小性・封じ込め・content hygiene・cross-skill 参照整合の 15 軸を扱う。

How it works仕組み

static scripts (collect → report, matrix, usage, permissions, assets, interface, shapeup, consistency, odd)静的スクリプト（collect→report・matrix・usage・permissions・assets・interface・shapeup・consistency・odd） → judgment axes via a fresh subagent判定軸は独立サブエージェントが担当 → report (Critical / Warning / Info)レポート（Critical / Warning / Info） → confirm fix scope修正範囲を確認 → apply → re-audit適用 → 再監査
番 Reviewer = Fresh Agent: judgment work — especially eval and fix — is delegated to an independent general-purpose subagent so the audit avoids the main session's self-evaluation bias. Reviewer = Fresh Agent の原則：判定作業、とくに eval と fix は独立した general-purpose サブエージェントへ委ね、メインセッションの自己評価バイアスを避ける。
