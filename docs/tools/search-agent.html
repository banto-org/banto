search-agent — mechanical grep, in parallelsearch-agent — 機械的な grep を並列で

search-agent is not called directly by the user. The search skill's deep path launches 3-5 of them in parallel on the haiku model, each running a handed-over regex group and returning only the top candidates — relevance judgment and summarization stay with the orchestrator.

search-agent はユーザーが直接呼ぶものではない。search skill の deep path が haiku モデルで 3〜5 体を並列起動し、渡された regex グループをそれぞれ機械的に実行して、トップ候補だけを返す。関連度判定や要約はオーケストレーター側が担う。

01

Allowed tools許可ツール

GrepGlobReadWrite
02

What it does何をするか

It receives search patterns, a target (directory or file), a per-category limit N (default: top 15 files per pattern, snippets under 120 chars), and a temp-file destination. It runs every Grep call in a single message — never serially, since parallel is 4-10x faster — and truncates huge files like full-combined.txt with -C 2 or a head limit rather than a raw cat.

受け取るのは検索パターン、対象（ディレクトリまたはファイル）、カテゴリごとの上限 N（既定：パターンあたり上位 15 ファイル、スニペット 120 字以内）、一時ファイルの出力先。複数の Grep は 1 メッセージ内で一度に呼ぶ（逐次実行はしない — 並列は 4〜10 倍速い）。巨大ファイル（full-combined.txt など）は生 cat をせず、-C 2 か行数上限で切り詰める。

All hits go into the temp file; the reply stays lightweight, capped at the given N, in a fixed machine-parseable format — a run reference, top candidates as file:line | matched_term | snippet, and any zero-hit patterns. Returning everything "to be helpful" is explicitly wrong — it would pollute the orchestrator's context.

全ヒットは一時ファイルへ書き、返信は上限 N までに絞った軽量な形式（run 参照・トップ候補を file:line | matched_term | snippet・ヒット 0 件のパターン一覧）に固定する。「全部返した方が親切」は明確に誤りで、オーケストレーターのコンテキストを汚染する。

03

When it firesいつ動くか

launched from search skill's deep pathfan out internal search in parallel judging relevance or summarizingexternal web researchediting files

Relevance judgment and summarization stay with the orchestrator (opus); external web research routes to research-agent; this agent never edits files.

関連度判定・要約はオーケストレーター（opus）が行う。外部 web リサーチは research-agent へ回る。このエージェントはファイル編集を行わない。

04

Invocation呼ばれ方

Only the search skill's deep path launches search-agent, 3-5 at a time in a single message, each on the haiku model, with a regex group, a target, a limit N, and a temp-file path already assigned.

search-agent を起動するのは search skill の deep path のみで、1 メッセージ内に 3〜5 体、それぞれ haiku モデル・regex グループ・対象・上限 N・一時ファイルパスをあらかじめ割り当てて起動する。

// search skill fans this out across 3-5 pattern groups, in parallel
Agent({
  subagent_type: "search-agent",
  model: "haiku",
  description: "Grep decisions for checkpoint-related terms",
  prompt: "Patterns: [checkpoint, save-checkpoint, idle.?checkpoint]. Target: {base}/decisions/. Limit N=15. Temp file: {base}/tmp/search/run3-a.txt."
})
05

How it works仕組み

1. receive pattern group
→
2. Grep in parallel
→
3. write all hits to temp file
→
4. return top N candidates
番

When launched with a schema (StructuredOutput) from a Workflow, it returns the same information as an array of {file, line, snippet, matched_term} instead of formatted text — the schema validates it.

Workflow から schema（StructuredOutput）付きで起動された場合は、テキスト整形の代わりに {file, line, snippet, matched_term} の配列で同じ情報を返す（schema が検証する）。
